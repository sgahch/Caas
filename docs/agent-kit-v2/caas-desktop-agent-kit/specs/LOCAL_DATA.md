# CaaS v2 本地数据与发布协议

本规格是本版数据保存、管理发布与恢复的统一依据。采用 Electron 主进程 DesktopStateService 与 SqliteStateStore，SQLite 真实保存版本化演示状态；渲染端 DesktopRepository 只适配 IPC。本文件只定义实施要求，尚未进行应用和 Windows 测试。

## 1 桌面持久化的最小结构

### 1.1 可信写入端与存储边界

- 只由一个桌面可信进程持有写入入口，渲染端调用明确的命令，不接受任意 SQL，也不接受普通表单直接覆盖整份运行快照。
- 应用数据放在稳定的当前 Windows 用户数据目录，应用 ID 保持稳定；不得放在安装目录、临时解压目录或构建输出里。软件覆盖升级不能覆盖用户数据库。
- 第一版默认用 SQLite 中的版本化 JSON 快照保存中小规模演示业务，以复用现有 domain。但关系、计量、容量等领域校验仍由可信进程执行。
- 建议的最小数据组：`published_config`、`scenario_baseline`、`runtime_state`、单行 `cms_draft`、`events`、`command_results`、本机 `local_admin`、素材清单及 `app_meta`。实际表数可合并，责任边界不能混淆。
- 本机密码与会话不属于 DemoState，也不通过展示端快照返回。

### 1.2 版本与命令

app_meta 保存数据库 schemaVersion、configRevision、businessRevision、runtimeRevision、runId、demoNow、lastMeteredAt 和 clockState。应用程序 appVersion、种子 seedVersion 与 schemaVersion 分开，不以界面名称充当程序身份。

| 变化 | configRevision | businessRevision | runtimeRevision | runId |
|---|---|---|---|---|
| 纯计量、遥测与曲线 tick | 不变 | 不变 | 增加 | 不变 |
| 展示文案、地图点位、未来速率等配置应用 | 增加 | 通常不变 | 增加 | 不变 |
| 调度、终止、续租、告警状态等业务动作 | 不变 | 增加 | 增加 | 不变 |
| tick 中的到期终止或资格变化 | 不变 | 增加 | 增加 | 不变 |
| 进入维护或改变全局播放状态 | 不变 | 增加 | 增加 | 不变 |
| 应用结构场景或恢复内容包 | 增加 | 增加 | 增加 | 新值 |
| 重置本轮演示 | 不变 | 增加 | 增加 | 新值 |
| 恢复出厂内容 | 增加 | 增加 | 增加 | 新值 |

configRevision 保护已发布内容的编辑基准；businessRevision 保护会影响业务操作的状态与约束；runtimeRevision 是整个展示快照的序号，配置发布也必须增加它。不能用随着计量频繁变化的 runtimeRevision 对普通业务动作做严格 CAS，否则 30 秒才刷新一次的界面会不断遇到假冲突。按实际影响分类，而非按调用来源分类；调度资格等业务约束即使存放在配置表也须增加 businessRevision。

普通命令携带 `{ requestId, runId, expectedBusinessRevision, command }`。主进程先验证窗口权限、维护状态与 runId，再查询同运行内幂等结果；同键同请求返回已记录结果，同键不同内容拒绝。幂等查验先于 businessRevision CAS；若基准真正过期，返回冲突并保留用户选择，不自动换版本重做终止或续租。

全部写入与模拟推进经同一个队列。事务内按最新状态结算到生效时刻，重新检查目标节点、实体状态和容量，然后完整提交实体、计量、事件、幂等结果与版本。提交失败全部回滚，提交成功后才广播变化。快照 events 从独立事件表组装，不在 runtime JSON 另存第二份权威数组。

查询、进入页面、打开草稿和预览不推进时钟。窗口以 runtimeRevision 判断整份快照新旧；runId 切换由可信主进程通知或成功结果建立，旧运行迟到响应不能触发切回。重置、导入和恢复后，本机 revision 继续递增，导入包中的版本仅作为来源元数据，不覆盖本机序号。


## 2 一个草稿与两种应用方式

### 2.1 草稿字段与预览

全应用只保留一个工作草稿，另用 draftRevision 与有序自动保存避免旧表单请求覆盖较新编辑。至少记录 `draftBaseConfigRevision、sourceRunId、sourceBusinessRevision、changeType、savedAt` 及修改内容。界面提供“保存草稿”“预览”“保存并应用”，不加入审批环节。

- 保存草稿只写草稿区；展示端只读取已经发布的配置与当前运行状态。
- 预览使用独立的只读视图，不能让预览按钮、曲线刷新或计量逻辑写回正式运行。
- 未保存的表单关闭前提示保存／放弃／取消；已保存草稿重启后仍在。不能把内存中的表单误称为已持久化草稿。
- 应用类型由可信端按被修改字段分类，不信任前端传来的“这是配置修改”标志。一个草稿如果包含结构或历史数据变化，整体提升为场景替换类型，不部分悄悄应用。

### 2.2 类型一 展示配置合并

适用：平台名称、标题、说明、显示名称、型号的展示标签、样式／素材引用，以及已定义的未来遥测生成设置。稳定实体 ID、关联关系、资源容量、订单价格快照与历史计量不在这一白名单内。

1. 只提交配置差异，不携带旧的 `runtime_state`。
2. 校验 `draftBaseConfigRevision == 当前 configRevision`。不比较草稿建立时的 runtimeRevision，因此正常 Token 刷新不会让一条文案修改持续发生冲突。发布后同时增加 configRevision 和 runtimeRevision，businessRevision 在未改变业务约束时保持。
3. 在写入队列中先按旧速率结算到本次生效时刻，再合并配置。之后的新时间段使用新参数，既有输出与账单不变。
4. 配置、素材引用、必要计量、事件和新版本一次提交；清空已应用草稿并通知展示端重新读取。
5. 若配置版本确实已变更，保留草稿并提示重新核对差异，不自动覆盖，不静默采用最后写入者获胜。

例：修改机房显示名称、平台名或后续 Token 速率，不得把已终止订单改回运行、把当日计量降回草稿建立时数值，或重写历史账单。修改产品目录价如被列入配置，只影响之后新建的演示订单；已有合同价格快照不随目录改变。

遥测参数应明确支持的模式，例如“固定值”和“模拟波动”。管理员保存固定 GPU 利用率后，下一次刷新仍按固定值显示；不能后台刚保存就被随机数覆盖。修改历史曲线、当日／累计 Token 基数则属于场景替换。

### 2.3 类型二 演示场景整体替换

适用：节点／租户／型号实体增删、容量、关联关系、实例及订单状态、已有合同价格、历史账单、Token 基数、历史用量与事件等。派生 KPI 仍从源记录计算；CMS 应提供源记录编辑入口，不另设一套与明细矛盾的首页数字。

1. 开始结构编辑时提示并进入“暂停编辑”：结算到暂停点，暂停模拟时钟，暂时禁用展示端会修改运行状态的按钮；读取和展示仍可使用。
2. 此时建立结构草稿，固定 `sourceRunId / sourceBusinessRevision`。保存草稿不替换正式数据，也不会改写既有账单。
3. 预览校验所有必需关联、资源守恒、X1 约束、时间段、整数金额及计量关系。容量不能低于该草稿中已保留的配额；删除有引用的实体必须一并明确处理引用，否则拒绝应用。
4. “保存并应用”展示影响摘要：新增／删除记录数、运行订单与实例变化、历史账单变化、GPU／CPU 总量与分配、Token 与租金前后值，明确这是替换当前演示场景。
5. 在确认后、真正替换前生成一份可恢复的旧业务 JSON 快照。备份失败则不覆盖旧场景。默认保留最近 3 份自动内容备份，不扩成版本管理系统；不能删除仍被备份引用的素材。
6. 检查编辑基准没有变化，事务中替换业务场景、更新基线和配置、设置新 `runId`、更新版本并清空草稿。全程不动本机管理凭据。
7. 应用完成后默认仍暂停，让管理员核对结果，再显式继续演示；重置计时基准，不补算编辑期间的 Token。旧计时器及旧命令因运行 ID 不符而失效。

允许管理员在这一独立场景草稿中修订演示账单样例，以满足“展示信息可编辑”。它不是对正在运行的旧账本悄悄改金额：旧运行保存在回退快照中；普通终止／续租／刷新继续遵守账单保护规则。

“放弃结构编辑”保留正式场景，退出编辑后恢复原有播放状态。应用在暂停编辑期间关闭，重开时正式数据不变、草稿保留且仍暂停，不能启动时自行发布草稿。

### 2.4 模拟时钟的并发保护

配置合并、业务操作、暂停编辑和恢复导入均通过同一队列。任何改变生产速率或实例状态的动作，先结算旧状态截至生效时刻；下一次 tick 只结算之后的区间。两次刷新同一个区间不得重复累计。

后台停止、退出、系统休眠及结构编辑暂停期间默认不补算 Token。应用恢复时用已保存的 demoNow 继续，并重建当前会话的计时基准。草稿的“过去快照”绝不能成为新的实时订单状态来源。

## 3 本地账号和权限的真实边界

默认只提供一个本机管理员账号，不增加多用户管理。首次进入管理端由使用者设置密码，不打包开发者账号或通用默认密码。密码使用成熟密码哈希实现和独立随机盐保存，不明文存储；具体实现由桌面技术方案锁定。

| 使用状态 | 允许 | 不允许 |
|---|---|---|
| 演示模式 | 浏览页面、执行原有模拟调度／终止／续租／迁移／告警动作、在约定入口重置本轮演示 | 进入 CMS 读取管理草稿、修改发布内容、整体恢复数据、恢复出厂内容、修改管理员密码 |
| 已认证本机管理员 | 管理草稿、预览、应用配置／场景、导出及恢复完整业务备份、修改自己的本机密码 | 获得未经实现的云端租户权限或真实算力供应商权限 |

- 可信端检查每一个管理命令的认证状态和权限，不能只隐藏菜单或让渲染端声明自己是 admin。CMS 退出登录或应用重启后，管理会话失效。
- 展示顶部的“当前租户／角色”仍可作为演示内容编辑，与真实本机管理员权限分开；把展示角色改成“管理员”不会获得 CMS 权限。
- 本地权限防止未经认证者通过应用正常入口修改 CMS；不承诺阻止拥有 Windows 管理权限的人直接修改文件或逆向程序。数据库和 JSON 备份也不因此自动具备加密功能。
- 至少实现首次设密、登录、退出、改密。若增加忘记密码恢复，必须作为明确的离线恢复流程设计，不能留一个任何人都能点击的免认证重置管理权限按钮。本次不因此加入短信、实名或联网登录。

## 4 整包 JSON 备份和恢复

### 4.1 备份内容

备份是业务数据包，不是账号迁移包。建议外层结构为 `backupFormatVersion、schemaVersion、appVersion、exportedAt、payload、assetManifest`。

`payload` 包含：已发布配置、当前场景基线、当前运行数据、模拟时钟、全部关联记录、历史账单与用量、Token 计量、填充去重标记、业务事件以及当前已保存草稿。草稿恢复后仍未应用，不能被当作已发布配置。

必须排除整个本机认证／会话存储：密码、密码哈希、盐、恢复凭据、会话令牌等均不导出。导入也不能替换或创建管理凭据；目标机使用自己设置的账号密码。

CMS 上传的图片等素材必须随 JSON 以受限的内容数据带走，不能只保存源电脑的绝对文件路径。应用自带的地图／字体可以使用受版本校验的内置资源 ID，但目标安装包必须已包含相应资源。记录并执行单素材与整包大小上限，超限在写入前给出提示。

导出时读取一个一致的已提交快照，记录相应配置与运行版本；不能前半份来自修改前、后半份来自修改后。摘要用于发现损坏，不把摘要当作来源认证或加密。

### 4.2 恢复顺序

1. 管理员选择 JSON，先检查体积、格式版本、必填字段、重复 ID、关联、枚举、容量、时间段和金额；未来不支持的格式拒绝，不先清空当前库。
2. 在临时区域完成旧支持版本的数据转换以及素材完整性检查。不得接受任意目标文件路径或执行导入内容中的代码。
3. 在隔离预览中展示正式数据与未应用草稿的替换摘要。取消不改变当前播放、草稿或备份；确认后才进入维护暂停，生成一次当前业务备份，再执行替换。
4. 素材先写入独立的新版本目录；数据库事务只切换到已经准备好的素材引用和新业务数据。失败时旧引用保留，清理未用的新目录；不能声称数据库事务会自动回滚任意文件写入。
5. 事务提交后采用新的运行 ID 和版本，拒绝旧窗口的迟到命令；保持导入的 demoNow，默认暂停，管理员核对后继续。导入的草稿若仍与导入配置同源可重新关联基准，否则标为待核对，不能自动覆盖。
6. 校验本机账号仍可用且没有被备份中的字段改变。导出时的源运行 ID 可以保留为来源说明，不能沿用为当前命令的有效运行 ID。

恢复是显式业务替换操作，不是普通 CMS 保存。损坏文件、非法关系或写入失败时应保持当前正式数据完整可用。

## 5 重启、迁移和多电脑离线行为

### 5.1 重启与软件升级

- 成功保存的配置、运行动作、已保存草稿和素材引用，正常退出或结束进程后重启均应恢复。中途故障只能得到完整旧状态或完整新状态，不能出现已扣资源但没有订单等半更新。
- 数据库迁移在业务窗口开放写入前完成；记录 schemaVersion，按有序脚本升级，在一致性备份后执行。失败时停止新版本写入并给出回退说明，不自动初始化成出厂样例。
- 技术层的数据库回退必须使用适合当前数据库状态的一致性备份方法，不以运行中随意复制单个文件充当完整数据库备份。对用户可转移的备份仍使用上述排除认证数据的 JSON 格式。
- 更换安装目录或覆盖安装同一应用 ID 的新版本，保持原用户数据目录。卸载的数据保留／清除行为必须在说明中明确；清除用户内容必须是明确选项。

### 5.2 多台电脑

- 默认每个 Windows 用户配置目录拥有独立数据库和本机管理账号。发给第二台电脑的 EXE 是程序与初始模板，不会自动带走第一台电脑的管理账号或后来编辑的数据。
- 通过 JSON 手动迁移已编辑业务内容；导入后两台机器分别运行，后续修改互不影响、不会自动同步。
- EXE 制作和发布前检查安装包内没有开发数据库、演示过程中遗留的账号、未公开内容或旧测试日志。
- “重置本轮演示”从当前已发布场景基线生成新运行，并保留 CMS；“恢复出厂样例”由管理员执行，先备份并说明将清掉哪些自定义展示内容。

### 5.3 两个复位命令不得混用

- `resetCurrentRun`：从**当前已发布的场景基线**重建运行状态，只清除基线之后的本轮操作进度；保留已发布 CMS 配置、自定义业务内容、本机管理员、应用身份以及可继续使用的配置草稿。保留基线自带的历史记录和处理标记，只移除本轮新增的进度，不简单清空所有历史数组。生成新 runId，不因复位增加 configRevision；businessRevision 与 runtimeRevision 均增加。结构维护暂停期间禁止从展示端绕过锁执行这一命令。
- `restoreFactoryContent`：恢复随本版本交付的标准出厂演示内容、配置和基线，清理未应用草稿及当前运行进度。必须先生成业务备份、展示影响摘要并由管理员确认；保留本地管理员、程序身份、数据目录和当前数据库结构版本。不能把“恢复内容”做成删除整个用户目录或重建账号。
- 原三条业务场景中的 320 GPU、286400 元及后续精确数字，应先执行 `restoreFactoryContent` 进入标准种子，再用 `resetCurrentRun` 逐条独立运行。用户已经编辑并应用场景时，`resetCurrentRun` 应回到该自定义基线，不能仍假定回到 320 GPU。


## 6 数据包与素材的具体默认值

对外统一一种 .caas.json 内容包，用于手工导出、自动业务回退和跨电脑迁移，包含已发布配置、当前基线、当前运行态、保存的草稿及必要素材。导出窗口说明是否存在未应用草稿；导入后的草稿仍未发布。初版不增加“只导出草稿”的第二套格式或跨库增量合并。

文件读取前限制总大小 50 MiB；单图片上限 5 MiB、解码后不超过 2048×2048，支持 PNG、JPEG、WebP。图片通过主进程选择、校验并按内容哈希复制到资产目录。包内用户图片以受限 base64 内容携带，随包地图和字体使用内置资源 ID 与版本校验。限制是本项目默认值，不是外部服务规则。

SHA-256 校验针对明确序列化的 payload/素材字节，字段顺序规则写入格式说明；校验仅识别意外损坏，不用于证明数据来源。整数金额、计数与数量必须为安全整数，百分比和时间范围按 DATA_RULES 校验。

正式配置、基线与运行态必须通过完整领域校验。草稿允许暂时缺少业务引用，但仍需通过结构、大小、字段类型和素材安全校验；恢复后保持未应用并提示补齐，不能因为包含未完成草稿就拒绝自己导出的完整备份。

导入先在临时隔离区解析、校验和预览，不占用或覆盖当前唯一编辑草稿。用户确认整体恢复时，进入维护模式并备份原内容；若原草稿将被替换，摘要明确提示。恢复后使用新的本机版本与 runId，导入草稿的配置基准按新配置重新绑定或标为待核对。

文件准备与数据库事务是不同阶段：先把新素材写到独立目录，完成校验后事务切换引用；失败保留旧引用，孤立的新素材可稍后清理。当前发布、基线、草稿和保留备份引用的素材都不能立即删除。

用户可见内容恢复永不替换 local_admin。原生数据库一致备份仅用于同机升级故障回退，文件留在受限的内部备份目录，不与 .caas.json 混作一种导入格式。

## 7 关闭维护与恢复后的默认状态

结构应用、内容导入和备份恢复完成后保持暂停，界面提供“继续演示”；读取与查看仍可用。放弃结构草稿不改正式场景，恢复进入维护前的播放状态。维护中退出或崩溃，重启后继续暂停并提供继续编辑或放弃，不能偷偷开始计量。

重置本轮按原发布基线恢复数据，并保留全局运行/暂停选择；新时间基准从主进程当前单调计时源建立。系统休眠和关闭期间不补算产出，避免恢复时凭空累计整个离线时长。

## 8 草稿升级与自动备份触发

配置草稿升级为结构草稿时，先结算并进入维护，保留原配置差异，结构部分从最新正式运行数据建立。维护基准在暂停提交后记录，避免按较早快照覆盖刚完成的订单动作。

普通配置应用无需生成自动内容备份；结构应用、导入恢复、备份恢复和恢复出厂在确认后、替换前仅生成一次。默认保留最近 3 份；内部数据库升级备份属于另一路技术回退，不计入这 3 份可迁移内容包。
