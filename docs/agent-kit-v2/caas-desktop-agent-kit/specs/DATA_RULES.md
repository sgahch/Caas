# CaaS 演示系统：统一数据、状态与验收规则

本节为 v2 桌面版的标准种子、状态、计费和剧本规范。所有价格、硬件容量、客户、曲线、Token 和调度均为演示假设。领域规则在 Electron 主进程执行，SQLite 真实保存，所有窗口通过受控 IPC 读取和执行动作；不依赖 HTTP 服务。后台编辑和发布细则见 LOCAL_DATA 与 ADMIN。

## 1. 必须先固定的口径

1. **容量、分配、实际利用率分别计算。**GPU 卡数、CPU 核数是资源容量；已分配 GPU 和首页“已用 CPU”取实例保留的资源配额；监控的 GPU／CPU 使用率来自遥测样本，不能用分配比例冒充。暂停和离线租赁实例的保留资源仍计入已分配。
2. 首页“空闲”按“总容量 − 已分配”显示，含义是未分配。真正可调度资源还必须过滤离线、异常和型号不匹配的节点。初始种子中，离线中心节点均已整节点出租，因此初始 108 张空闲卡全部位于在线节点。
3. **资源类型与实例类型分开。**租赁资源类型为 `bare_metal / gpu / whole_machine`；实例类型为 `bare_metal / edge`。首版 将三种中心租赁产品均映射成 `bare_metal` 实例。`bare_metal` 与 `whole_machine` 都在演示中独占一个中心节点，只保留产品名称区别；不推导虚拟化、容器或真实硬件隔离能力。
4. X1 只能运行 Token 业务：`orderId = null`、`gpuCards = 0`、租金为 0；使用独立的 `edgeUnits` 计量。芯片型号未提供，保存 `chipModel = null`，型号列显示“边缘算力芯片”，不得编造型号。下面的 CPU、内存、存储和算力单元容量都是用于凑齐演示总量的假设，不是 X1 产品规格。
5. 所有金额用**人民币分的整数**保存。容量统一用十进制 GB 保存，展示时 `1 TB = 1000 GB`；Token 用整数保存。`128.6M`、`8.42B`、`32TB` 等只在格式化层生成。
6. 固定演示时间从 `2026-10-19T10:00:00+08:00` 开始，统一使用 UTC+8 划分日期。首次加载种子呈现指定截图数值；之后允许按模拟时间累计。本章固定数值以恢复出厂标准内容后的基线为准；自定义场景复位使用其自己的发布基线。
7. “海外客户为主”通过样例租户实现：8 个客户租户中 6 个海外、2 个国内；24 个在租订单中 18 个海外、6 个国内。客户地区只保留既定两项；系统内部任务如没有客户，显示“—”。不因此增加外币、时区或英文系统。

## 2. 最小统一数据模型

主进程 DesktopStateService 通过 SqliteStateStore 持有唯一业务状态，所有窗口只读各自 Pinia 接收的同版本快照，经共用 selector 获取汇总。禁止各页面保存自己的订单副本、KPI 常量或随机生成的节点列表。

| 实体 | 最少必要字段 | 约束 |
|---|---|---|
| `DemoState` | `schemaVersion, seedVersion, configRevision, businessRevision, runtimeRevision, runId, demoNow, refreshSeconds, sites, tenants, nodes, tasks, instances, orders, usageRecords, tokenMeters, invoices, alerts, events, processedDemoEventIds` | 一次业务动作只提交一次完整状态变化；不保存可由其他实体推导的全局 KPI。 |
| `Site` | `id, name, kind` | 三个 `center` 和一个 `edge` 分类；出厂显示名为南宁智算中心、成都智算中心、内蒙古机房、边缘站点；管理端可改显示名，四个内部槽位和中心/边缘语义不变。 |
| `Tenant` | `id, name, customerRegion` | `customerRegion = overseas / domestic`；其他实体通过 `tenantId` 关联，避免客户地区在各页面不一致。 |
| `Node` | `id, siteId, deviceType, gpuModel, chipModel, capacity, status, lastReportAt, telemetry` | `capacity` 含 `gpuCards, cpuCores, memoryGB, storageGB, edgeUnits`；`status = online / offline / abnormal`。异常但仍有心跳计入在线数量，离线不计入。 |
| `Task` | `id, tenantId, orderId?, businessType, taskType, source, priority, requestedSpec, preferredSiteId?, preferredNodeId?, status, pausedFrom?, createdAt, failureReason?` | `businessType = rental / token`；任务来源是订单或系统任务。`preferredNodeId` 仅用于指定的边缘本地执行位置，不给普通租赁增加隐形的绑节点要求。 |
| `Instance` | `id, taskId, orderId?, tenantId, nodeId, instanceType, businessType, status, allocation, allocationHeld, startedAt, endedAt?, endReason?` | `allocation` 含 `gpuCards, cpuCores, memoryGB, edgeUnits`。单实例绑定单节点；同一任务最多一个未结束实例。资源统计以 `allocationHeld` 为准，终止后保留历史规格但改为 `false`。 |
| `Order` | `id, tenantId, resourceType, quantity, spec, billingMode, unitMonthlyPriceCents, contractPeriods, status, activatedAt?, actualEndedAt?` | `status = pending / running / ended / abnormal`；`quantity` 对 GPU 表示卡数，对裸金属／整机表示台数。一笔演示订单对应一个租赁任务、一个当前实例。 |
| `UsageRecord` | `id, instanceId, tenantId, orderId?, nodeId, businessType, resourceType, instanceType, startedAt, endedAt?, phase, allocation` | 保留资源时间段，左闭右开；phase 为 running/paused/error；同实例最多一个未闭合段，当前分配仍由实例计算。 |
| `TokenMeter` | `id, instanceId, usageRecordId, tenantId, nodeId, outputBeforeDemoDay, inputBeforeDemoDay, dailyCounters, demoOutputPerSecond` | `dailyCounters[date] = { inputTokens, outputTokens }`。历史量和每日增量分开，累计值由其求和得到；实例结束不删除计量记录。 |
| `Invoice` | `id, orderId, tenantId, periodStart, periodEnd, lineSnapshot, amountDueCents, paidCents, status, issuedAt, dueAt, settledAt?` | 已出账账单保存价格、数量、期间与金额快照；`status = unpaid / paid / overdue`。当前运行场景不修改已出账期间和金额；新场景样例编辑按 LOCAL_DATA 执行，不做退款。 |
| `Alert` | `id, nodeId, instanceId?, type, severity, status, disposition?, createdAt, processedAt?` | `status = unprocessed / processed`；确认／忽略分别保存 `confirmed / ignored`，均保留记录。处理告警不等于修复节点。 |
| `Event` | `id, entityType, entityId, action, message, createdAt` | 调度日志、实例事件和业务操作记录复用此结构；只记录演示动作，不声称审计能力。 |

`Node.telemetry`、实例曲线和近期 API 调用记录使用有界样本：每条曲线最多 60 个点、实例近期调用最多 20 条。界面注明“近期调用”，不要求这 20 条记录等于历史全部 Token。避免刷新不断累积无界数组。

DemoState 另保存 `lastMeteredAt`。所有会改变运行状态的命令，先按旧状态结算至命令生效的 demoNow，再改变任务/实例状态并推进 lastMeteredAt；随后刷新只计算新的区间。这样暂停/终止不会漏记此前已运行的时间，新任务不会补算启动前的 Token。测试可以冻结 demoNow 核对精确数值。

### 3.3 Token 初始计数

为上面的生产实例创建计量记录；表内“累计”用于计算 `outputBeforeDemoDay = 累计 − 当日`，不要另存一套全局累计数字。

| 生产节点 | 当日输出 Token | 累计输出 Token | 演示输出速率 |
|---|---:|---:|---:|
| `NN-11` | 32000000 | 2200000000 | 2400／秒 |
| `NN-12` | 18000000 | 1200000000 | 1600／秒 |
| `CD-09` | 26000000 | 1700000000 | 2200／秒 |
| `IM-07` | 24000000 | 1400000000 | 1800／秒 |
| `EDGE-01`—`EDGE-06`，每台 | 4000000 | 260000000 | 100／秒 |
| `EDGE-07` | 4600000 | 320000000 | 200／秒 |
| `EDGE-08`，历史记录 | 0 | 40000000 | 0 |

## 4. 统一 selector 与刷新规则

### 4.1 必须派生的数据

```text
totalGpu = sum(nodes.capacity.gpuCards)
allocatedGpu = sum(instances where allocationHeld, allocation.gpuCards)
idleGpu = totalGpu - allocatedGpu
totalCpu = sum(nodes.capacity.cpuCores)
usedCpu = sum(instances where allocationHeld, allocation.cpuCores)
idleCpu = totalCpu - usedCpu
onlineNodes = count(nodes where status != offline)
todayOutput = sum(tokenMeters.dailyCounters[demoDate].outputTokens)
cumulativeOutput = sum(tokenMeters.outputBeforeDemoDay + all daily outputTokens)
currentMonthlyRent = sum(仍有效的在租订单.unitMonthlyPriceCents × quantity)
```

“仍有效的在租订单”只包括已经激活、尚未终止且当前模拟时间仍在租期内的 `running / abnormal` 订单；待调度、已结束和仅约定未来开始的订单不计入。暂停实例但合同仍有效的订单继续计入。续租只延长租期，不能把同一订单的两段合同重复计入当前月租。

节点详情的已分配、节点列表、总览、订单绑定节点和实例清单全部从相同关联关系生成。`gpuCards` 只能表示数量，不能拿 GPU 利用率乘总卡数去反推订单或实例占用。

### 4.2 遥测与自动刷新

- 首页 GPU 利用率取有有效上报的中心节点 GPU 利用率，按物理卡数加权；内存、存储利用率分别用有效样本的已用容量之和除以对应总容量之和。离线节点没有新样本，显示“—／最后上报时间”，不把未知值伪造为 0 并混入平均值。
- 主进程只有一套全局演示时钟与计量推进源；展示窗口刷新频率默认 30 秒，可切换 10／30／60 秒。管理预览和查询不能另开计量定时器。切页不得新增重复推进源。遥测用带种子的波动函数生成，以便复现；利用率限制在 0—100，温度和时间均为演示样本。
- 模拟时间与计量只由主进程唯一的全局 tick 按本次会话非暂停期间经过的单调时间推进；展示窗口的自动刷新、手动刷新和切页仅读取最新已提交快照，不触发计量。关闭或重新打开业务页面不改变全局时钟；应用退出、系统休眠或维护暂停期间不补算，恢复时从已保存的 demoNow 重建计时基准。
- 仅当实例是 `running`、节点非离线且 `businessType = token` 时追加 Token。暂停、错误和已结束实例不追加；保留其历史累计。
- **刷新不加载新种子，不自动恢复订单或实例，不重新调度失败／暂停／终止任务，不重写账单。**全局时间推进或业务命令前结算达到已激活订单的合同截止时刻时，必须调用同一终止流程，按合同截止时刻关闭用量、生成一次最终账单并释放资源；到期终止的 actualEndedAt 取合同截止时刻，手动提前终止取命令生效的 demoNow。该业务变化同时增加 businessRevision 和 runtimeRevision，不另设第二套终止逻辑。
- 策略页的四个模板仅展示；首版 的优先级、抢占和回落效果在明确的“手动调度”演示流程内执行。无需后台常驻调度引擎，也不承诺持续创建 Token 任务。

## 5. 状态机与业务动作

### 5.1 任务和实例状态

任务状态：`pending → scheduling → running`；调度失败为 `failed`。补充原文遗漏的 `paused` 状态，中文为“已暂停”，加入筛选。`terminated` 为终态。

| 动作 | 可执行条件 | 结果与资源规则 |
|---|---|---|
| 手动调度 | 任务为 `pending` | 进入 `scheduling`，先计算完整方案，再一次性提交。成功创建实例并变为 `running`；失败为 `failed`，记录过滤原因，不部分占用资源。 |
| 暂停 | 任务为 `pending / running`；`scheduling` 禁用并提示调度进行中 | 保存 `pausedFrom` 并变为 `paused`。运行实例同步暂停，**继续保留全部资源**，Token 停止增长；待调度任务本来就没有资源。 |
| 恢复 | 任务为 `paused` | 同一位置按钮改为“恢复”。恢复到原 `pending / running`，不得创建重复实例；原节点已离线时不允许直接恢复运行。 |
| 重试 | 任务为 `failed` 且无保留中的实例 | 清除本次错误，回到 `pending`，再由手动调度执行。已有离线租赁预留时禁用普通重试，提示先迁移或终止，避免同一订单分配两份资源。 |
| 终止 Token 任务／实例 | 尚未终止 | 任务和实例终止，`allocationHeld = false`，记录结束时间；停止新增 Token，保留历史计量和日志。 |
| 终止租赁任务／实例 | 有仍有效的关联订单 | 调用统一的“终止订单”动作，确认文字说明会同步结束关联订单。不得只删实例而继续显示有效租约。 |

实例状态最少为 `running / paused / error / terminated`。正在调度仅体现在任务中；先不要创建一个半初始化的实例。离线租赁实例的 `error + allocationHeld` 合法，用于表示合同资源仍被保留。

### 5.2 租赁优先调度

1. 过滤非中心节点、离线／异常节点、型号不符和规格不足节点；优先指定机房，无合适候选才跨机房。同一机房内满足需求时，整节点空闲优先于承载其他实例的部分空闲，再按节点 ID 排序；边缘回落寻找中心候选也复用这条简单顺序。
2. 优先选择已有足够空闲容量的候选。若不足，可计算释放该节点上 **Token 业务**实例后的容量；不得抢占其他租赁实例，包括暂停或离线仍保留的租赁实例。
3. 只有完整方案能容纳订单时才提交：旧 Token 实例以 `preempted` 原因结束，释放资源，原 Token 任务回到 `pending`；新租赁实例一次性建立；订单从 `pending` 变为 `running`。
4. 被迁出的 Token 任务不在同一次刷新中自动重启。之后可单独手动调度；未匹配前不会再次占用刚出租的节点。
5. 日志必须能看到候选匹配、资源过滤、Token 迁出和最终绑定；这是一段前端状态模拟，不执行真实实例迁移。

### 5.3 边缘回落与普通迁移

- Token 任务先检查指定边缘节点的在线状态和剩余 `edgeUnits`；不足时按任务中的预置中心规格寻找空闲中心节点，创建 `bare_metal + token` 实例，仍然没有租赁订单和租金。
- 普通迁移仅选择同类型、同规格、在线且容量足够的兼容节点，保持 instanceId、taskId、orderId 和整体开始时间稳定。一次提交中关闭旧用量段、更新实例 nodeId、释放原节点、预留目标节点并开启新用量段；失败时原状态完全不变，选择当前节点为无操作。迁移后保留原 running/paused 状态；原为离线 error 的租赁实例在合法新节点恢复 running，并将关联失败任务和异常订单一并恢复运行，记录原因。
- “迁移中”来自命令 pending 的 UI 忙碌态，不是额外持久化实例状态。期间禁用重复或冲突操作。普通迁移不支持任意硬件转换；边缘到中心的形态通过指定新任务回落场景展示。
- TokenMeter 的旧段保留原 nodeId，迁移后建立从 0 开始的新节点计量段。实例详情跨段求和；节点历史按段的 nodeId 归属。抢占与普通迁移不同：抢占仍结束旧 Token 实例并重新排队任务。
- 告警确认／忽略只改变告警处理状态和处理时间，不恢复心跳、不解除资源占用、不把异常订单改为运行中。

### 5.4 订单终止必须幂等

`terminateOrder(orderId)` 必须在同一次状态更新中执行：

1. 若订单已结束，直接返回既有结果，不再次记账、释放或生成日志。
2. 若订单尚未激活（activatedAt 为空），只取消其任务并结束订单，不根据计划开始时间生成用量或最终账单；此分支不进入后续计费。
3. 对已激活订单固定 `actualEndedAt`，终止关联任务和当前实例，释放仍保留的资源。
4. 对尚未出账且不与既有账期重叠的实际使用期间，按本节公式形成一次最终账单；若该期间已出账则不再创建。
5. 订单改为 `ended`，从当前月租汇总剔除；保留历史订单、合同、用量、Token 和账单。
6. 刷新、重载以及重复点击不能让订单复活，也不能重复出具最终账单。

## 6. 演示计量与租金公式

### 6.1 租金和订单金额

月度等值租金：`unitMonthlyPriceCents × quantity`。GPU 单价按卡，裸金属／整机单价按台；边缘任务没有此价格。

- 采用 **30 天一个演示账期**，不实现自然月长度差异。
- 按天收费时，从计费开始到计费截止按正持续时间向上取整为天数；0 秒为 0 天。日价保留为“月价／30”的有理数，不能先把日价四舍五入后再乘天数。
- 按月完整账期收费为一个月度等值租金；当前尚未出账的不足 30 天期间按同样日比例结算。已出账的完整期间不因后续终止而自动退款或重算。
- 统一公式：`amountCents = roundHalfUp(unitMonthlyPriceCents × quantity × billableDays / 30)`；完整 30 天自然得到整月金额。
- 正整数的四舍五入可使用 `floor((2 × numerator + denominator) / (2 × denominator))`；金额分只在最终金额处舍入一次。
- 表格“订单总金额”固定表示**已约定的合同金额**，从 `contractPeriods` 的金额快照求和；续租增加合同段与总金额。终止记录实际结束和最终账单，不把“合同金额”偷偷改成“已支付金额”，也不重写过去的合同段。详情分别列出合同、用量和实际账单。

续租只对已经激活且未结束的 running/abnormal 订单开放，待调度订单不续租；默认追加 30 天，表单也支持按原 billingMode 输入正整数天数或演示月数（月数乘 30）；在原约定结束时间之后追加一段价格快照，不改变已生效段、不再次计入当前月租。运行期不做任意调价、退款、支付接口和税费。管理端可在新场景内编辑价格样例，但不能反向改写当前已出账记录。

### 6.2 用量单位

- UsageRecord 是实际资源保留区间，统一左闭右开 `[startedAt, endedAt)`，未结束段以 demoNow 截止。暂停、恢复、进入 error 或迁移时关闭旧段并在同一时刻开新段；终止只关闭最后一段。当前分配从实例读取，不把历史段累加到当前分配。
- 与所选时间范围求交后，`卡·天 = GPU 卡数 × 相交秒数 / 86400`；`卡·月 = 卡·天 / 30`。边缘使用 `算力单元·天 = 单元数 × 相交秒数 / 86400`。小时详情同理计算，但面向用户的主表仍使用原需求单位。
- 实际保留用量与收费取整分开：不得给每个小时、暂停段或迁移段分别向上取整收费。租金在一个完整未结算区间上用统一公式取整天数。GPU 按卡计价，整机/裸金属按台；一台 8 卡设备运行 30 天是 240 卡·天/8 卡·月，12800 元月租仍只收 12800 元。
- 边缘单价显示“—”，设备应收为 0；暂停与错误保留段计资源用量但不产生 Token。历史用量和 Token 不因实例迁移或终止而移动、删除。
- 中心自营 Token 实例也没有租赁应收款。不能仅因为实例类型是裸金属就给它计算设备租金。
- 租赁用量按合同保留资源计，暂停和离线保留期仍计量；Token 生产量按实际处于运行状态的模拟时间计，两者不混用。这是明确的演示假设，不代表对客户的真实计费承诺。

### 6.3 账单不可被当前状态反向改写

账单列表直接读 `Invoice` 快照，不通过“当前实例有没有终止”重新计算旧账单。已支付账单的金额、期间、已收金额、结算时间必须保持不变；其他已出账账单也不自动变更金额。待支付／逾期仅是收款状态，不决定合同资源是否自动释放。

CSV 默认导出当前筛选及排序后的**全部命中记录**，不只导出当前页。用量和账单分别导出；中文 UTF-8 BOM，金额写十进制元，保留表头和单位，正确转义逗号、引号、换行。CSV 数据与页面必须走同一个 selector。


### 6.4 时间过滤与汇总价格

用量统计的时间范围只切取资源用量与应计费用；“当日 Token”始终是 demoNow 所在 UTC+8 日期，“累计 Token”始终为样例基线至 demoNow，不能不改标题就变成所选区间 Token。资源类型和租户/地区过滤可以约束对应产出；两个不同时间口径在表头提示中说明。

用量按租户、客户地区、资源类型汇总；同组存在不同 SKU 或单价时显示“多档”，详情列明价格，不制造一个假平均价。历史账单按 Invoice 快照显示，当前未出账应计费用按统一公式计算；筛选费用时逐笔费用段与所选范围求交，最后按费用行取整分，不让总览反算旧账单。

## 7. 三条独立完整演示场景

精确验收先恢复出厂标准内容，再将每条场景从同一标准基线分别执行。用户修改过场景后，“重置本轮演示”回到当前发布基线，不会偷偷清除 CMS 设置；只有恢复标准种子后才核对本章固定数值。场景不增加实际硬件、付款或外部 API 依赖。

### 场景一：租赁订单优先，Token 任务迁出

**入口：**任务队列选择 `ORD-DEMO-LEASE` 对应的待调度任务，点击“手动调度”。

1. 需求为南宁 H100（GPU_A）8 卡整机。`NN-01`—`NN-10` 已被租赁占用，其中 `NN-10` 离线；唯一可释放的 H100 候选是 `NN-11` 上的 8 卡 Token 实例。
2. 日志显示型号与机房匹配、其他租赁不可抢占、释放 `NN-11` Token 实例、创建租赁实例。
3. 旧 Token 实例终止并保留历史产出，其任务回到待调度；新租赁实例预留 `NN-11` 的 8 卡、256 核和 1000 GB。

**验收：**

- 订单运行中，绑定 `NN-11`；实例类型为裸金属、业务类型为租赁。
- GPU 已分配仍为 **212**、空闲仍为 **108**，因为 8 张卡从 Token 切换到租赁。
- CPU 已用从 **5120 变为 5248**，空闲为 **2944**；月租从 **286400 变为 299200 元**。
- 旧 Token 累计不减少；原实例后续不再增加 Token；其他运行实例仍可正常产生 Token。
- 重复点击、刷新、重载后仍只有一份租赁分配，没有重复月租或复活的旧实例。

### 场景二：边缘本地资源不足，任务回落中心

**入口：**任务队列选择 `TASK-DEMO-EDGE`，点击“手动调度”。

1. `EDGE-07` 总计 8 单元，已有实例保留 4 单元，只剩 4 单元，不能容纳新任务所需的 6 单元；记录资源过滤原因并产生一条“边缘算力过载”警告。
2. 保留原边缘实例继续运行；按任务预置回落规格，在内蒙古首个满足条件的空闲节点 `IM-08` 创建 4 卡、64 核、128 GB 的中心 Token 实例。
3. 新实例类型为裸金属，任务类型为 Token 推理，订单为空，租金为 0；新输出只记在 `IM-08`。
4. 进入告警中心确认告警，再跳转 `EDGE-07` 节点详情；告警变为已处理，原节点与实例不会因此自动变更资源。

**验收：**

- GPU 已分配为 **216**、空闲为 **104**；CPU 已用为 **5184**、空闲为 **3008**。
- 当前月租仍为 **286400 元**，在线节点仍为 **44/48**。
- X1 没有租赁订单，旧边缘实例没有被误终止；计量新增的是中心生产记录，没有两边重复累计。
- 告警确认后仍可查看处理记录；刷新不再次创建同一个实例或同一未变化条件的重复告警。

### 场景三：终止租约、释放资源、保留已支付账单

**入口：**租赁订单中打开 `ORD-CD-01`，查看 13200 元已支付的历史账单，再终止订单。测试时冻结模拟时间为初始的 10 月 19 日 10:00。

1. 历史已支付期间为 9 月 1 日至 10 月 1 日，金额 13200 元，保持原样。
2. 当前未出账期间自 10 月 1 日起，截止到终止为 18 天 10 小时，按约定向上取整为 **19 天**，最终账单 `13200 × 19 / 30 = 8360 元`，状态待支付。
3. 关联任务、实例和订单终止，释放 `CD-01` 的 8 卡、192 核及其内存；合同历史和已产生的计量记录保留。
4. 去计量计费按该租户筛选，导出账单 CSV；切页、刷新、重新打开系统，再查看相同结果。

**验收：**

- GPU 已分配为 **204**、空闲为 **116**；CPU 已用为 **4928**、空闲为 **3264**。
- 当前月租为 **273200 元**，在线节点仍为 **44/48**。
- 历史 13200 元账单的期间、金额、已收金额和结算时间逐字段不变；只增加一张 8360 元最终账单。
- 重复终止不重复释放，不多生成账单；已结束订单和实例在 10／30／60 秒刷新及页面重载后均不复活。
- CSV 包含该租户当前筛选范围内的全部账单，与页面金额一致，不仅限于当前分页。


### 场景三后续：受控演示空闲填充

先核对场景三的终止数值，再点击演示设置中的“演示空闲填充”，模拟系统响应资源释放事件。此分支是 首版 必需演示，不由刷新定时器执行，不全量扫描或无限创建任务。首次成功终止 ORD-CD-01 时生成稳定的资源释放事件 `release:ORD-CD-01:<原实例ID>`；填充只响应这一次事件。

校验原订单已结束、原实例已释放、CD-01 在线且足够空闲后，一次提交预定义 A100 8 卡、CPU 64 核、内存 256 GB 的系统 Token 任务与实例、用量段和从 0 开始的计量段。任务无订单、无租金。条件不满足保持原状态，提示资源不可用，不寻找别的节点造任务。

同一次提交保存 `fill:<releaseEventId>` 完成标记；此标记独立于填充实例存活状态。重复点击、刷新、重载只返回已经执行的结果；即使填充实例后续终止或被抢占，也不得因缺少运行实例而重新生成。resetCurrentRun 仅移除当前发布基线之后产生的本轮事件与处理标记；只有回到尚未包含该次释放事件和填充完成标记的基线，再重新执行终止流程，才允许再次演示填充。基线自带的历史事件与处理标记继续保留。

填充后 GPU 为 **212/108**，CPU 为 **4992/3200**，月租仍为 **273200 元**，在线节点仍为 **44/48**。原租约仍已结束，旧账单和 8360 元最终账单不变；新任务只产生后续 Token。客户端界面使用“系统自动任务”的业务含义，演示设置用于推进剧本，不声称实现了常驻调度服务。

## 8. 桌面持久化与最少必要测试

### 8.1 桌面持久化与管理边界

- SQLite 保存在固定 userData 业务子目录。所有命令和模拟 tick 由主进程串行执行，先结算旧运行区间，再在事务中写实体、账单、事件、去重键及 revision。提交后才更新窗口。
- 快照携带 schemaVersion、configRevision、businessRevision、runtimeRevision、runId 和模拟时钟；旧窗口响应、旧场景异步回调与重复请求不能覆盖新状态。重复 requestId 返回先前结果或明确无额外动作。
- 管理端只有一个可恢复草稿。纯展示配置应用白名单 patch，不携带旧 runtime 快照；修改节点容量、关联、历史账单或 Token 基线必须先进入维护模式，暂停计量和业务写入，然后校验并整体应用场景。完整协议见 LOCAL_DATA。
- 运行期账单金额不可直接改写；准备新演示金额样例时编辑新场景，备份、校验、整体载入。这是演示数据重置，不是生产账单冲正或退款。
- “重置本轮演示”从当前 publishedBaseline 生成新 runId，保留 CMS 配置；“恢复出厂内容”恢复原始标准场景和默认内容配置，需先备份确认，保留管理员凭据和应用身份。
- 关闭应用不补算模拟时间。维护中退出，下次恢复维护状态并提示继续或放弃，不无提示地以旧基线重新运行。
- 升级有明确 schema migration 与恢复策略；写入、迁移、导入失败保持原有效状态，不静默清空。业务存储不能退回 localStorage。
- 全部可见编号可通过 displayCode 调整，内部 id 不变；主键、枚举、单位和资源守恒属于结构约束。后台必须提供合法关系表单，不能让管理员直接写任意 SQL 或 JSON 到正式状态。

### 8.2 必须有的规则测试

仅为下列会直接破坏演示可信度的规则写测试，不为每个展示组件重复造测试：

1. **种子守恒：**断言 48 节点、44 在线、GPU `320/212/108`、CPU `8192/5120/3072`、内存 32 TB、存储 512 TB、Token `128600000/8420000000`、月租 `28640000` 分；逐节点分配不超过容量，边缘 GPU 和租金为 0。
2. **调度原子性：**场景一成功后数据满足指定数值；失败方案不得先释放旧任务；任何租赁预留都不能被抢占。暂停不释放配额，恢复不重复分配。
3. **边缘与计量边界：**场景二不生成租赁订单，Token 只归属实际执行节点；暂停／终止实例刷新后计量不增长，历史累计不下降。
4. **账单快照与幂等：**场景三终止两次，只出现一张最终账单，历史已支付账单深度比较不变；30 天、19 天、0 秒、刚满一天等边界金额正确。续租不重复增加当前月租，不修改旧价。
5. **持久化与刷新：**执行一次终止后序列化、重新加载，再刷新三次，状态和资源占用不回滚；同秒重复刷新不重复计量；切换页面不叠加定时器。
6. **导出一致性：**过滤结果超过一页时导出的记录数等于全部命中行数，金额与单位一致，中文及包含逗号／引号的字段能正确解析。

页面视觉、字段完整性和三条完整演示流程做一次人工验收即可；首版 不增加性能压测、真实硬件联调或生产计费测试。


补充两条针对实际剩余风险的断言：普通迁移前后 instanceId 稳定、用量段不重叠、历史 Token 不换节点、当前资源守恒；同一个 fill 事件触发两次只产生一份实例，终止填充实例后重载并重试也不复活。

## 9 新增的桌面数据测试

在本章原业务测试之外，增加：品牌配置应用不回滚终止订单；维护期间拒绝运行命令；故意中断场景应用不出现半份资源；数据库保存失败不广播成功；两个窗口并发读取不重复 Token；重启恢复当前数据与草稿；旧 runId 回调被拒绝；导入损坏或不兼容包保持原数据；重置本轮保留 CMS，恢复出厂保留本地账号。全部验收结果在最终 exe 上记录，不预先标成通过。

## 10 v2 显示覆盖与保存来源

领域模型沿用本章实体。对外编号默认等于原内部 id，可由已发布配置中的 entityPresentation 覆盖为 displayCode；所有页面、结构化日志与 CSV 使用同一 selector。实体默认名称和编号保留，不能把显示重命名变成修改外键。新增对象即时采用默认展示值，再由管理端覆盖。

DemoState 中 events 是主进程从独立事件表组装的读取视图；SQLite runtime_state JSON 不另外维护一份可独立改动的事件权威。基线的历史事件作为基线样例保存，每次新运行将其有界、幂等地载入当前事件表；当前运行新增事件只写一次。历史完整查询经 getHistory 获取。

版本变化、维护锁和文件恢复协议以 LOCAL_DATA 为准。主进程业务 CAS 使用 expectedBusinessRevision 和 runId，不能用每个计量 tick 都改变的 runtimeRevision 让调度与终止持续冲突。配置发布同样推进完整快照 runtimeRevision，避免迟到的旧标题覆盖新配置。

## 11 到期边界的时间推进

若一次 tick 跨过多个合同截止点，应按时间先后分段结算到每个截止点，执行该时刻的统一到期终止，再继续推进到目标 demoNow。续租已经延长的合同采用当前有效的最终截止时间；未激活订单不产生使用租金。时间推进事务内若实际发生业务变化，businessRevision 只需随本次完整提交增加一次。

业务命令前若发现必须先处理的到期事件，应先提交系统结算事件并重验目标状态；原操作因此过期时返回最新快照和明确原因，不执行已经到期订单的续租或重复终止。不能在返回冲突时回滚必要的全局时间结算，也不能在一个失败的用户命令中留下部分用户动作。
