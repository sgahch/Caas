# CaaS v2 本地管理后台业务规格

## 1. 本次升级的明确含义

本规格定义 Windows 离线版本的内容编辑入口和完整字段覆盖。发布、维护、版本与导入恢复协议统一以 LOCAL_DATA 为准；本文件是实施要求，不是已完成应用的验收记录。

本次交付具有三个同时成立的特征：

1. **展示端与管理端各有独立入口。** 展示端沿用已批准的 3D 中国地图界面和八个业务视图；管理端负责编辑、预览、应用、备份和恢复。
2. **管理与保存是真实的本地功能。** 修改实际写入本机可写数据目录中的持久存储；关程序、重启 Windows 后能够恢复，不依赖浏览器缓存或改源码。
3. **算力业务仍是模拟。** 调度、迁移、设备心跳、Token、租金和账单均为演示数据，不对接真实算力租赁、短信、实名、支付或云端账户接口。

“后台可以改前端所有信息”的实现口径是：批准布局内的文案、品牌、编号、地图点位、业务原始数据、曲线样本和详情内容，都能从管理端找到对应编辑入口；汇总指标、关联字段和状态结果通过其来源数据或模拟命令改变。不是给每个数字提供一个互不关联的强制覆盖输入框。

固定内容包括页面结构、七个指标卡槽位、九张主表的业务字段结构、三个资源环图、3D 地图方向、业务枚举语义、计算规则、状态颜色含义和 X1 限制。首版不提供自由页面设计器、任意 HTML/CSS/脚本编辑、公式编程或调度规则编程。

### 1.1 对旧版范围的替换与保留

- 旧版“仅前端 + 浏览器持久化”不再足以描述本次升级；这次增加真实本地 CMS 和磁盘保存。
- 旧版可选的服务端实现思路可以复用，但不把“具备本地数据服务”写成“已接真实算力 API”。
- 现有数据实体、状态机、30 天演示账期、整数分计费、时间区间规则、Token 统计方式和幂等规则继续使用。
- 原展示端的手动调度、暂停/恢复、重试、终止、迁移、续租、确认/忽略告警等按钮继续执行模拟命令；不得把展示端误做成只剩静态浏览。
- “展示端读取已应用配置”只意味着它不直接修改管理配置，不意味着禁止上述业务交互。
- 单机离线为默认环境。同一台电脑的两个入口访问同一份本地数据；不同电脑各有独立数据，不会自动同步。需要迁移时使用导出/导入包。

## 2. 管理端菜单与页面职责

首版采用八个管理入口，各入口内部用标签页组织，避免为每类数据创建多套相似后台。

| 管理入口 | 内部内容 | 主要操作 |
|---|---|---|
| A01 工作台与应用 | 当前方案、单个草稿、变化摘要、预览、校验结果、本地备份 | 打开展示端、保存并应用、导入/导出、恢复备份、重置本轮、恢复出厂内容 |
| A02 品牌与界面文字 | 系统名称、Logo、演示身份、UiCopy 文案注册表、表格显示默认值 | 编辑、检索文案、按模块恢复默认、即时预览 |
| A03 机房、地图与资源 | 四个机房槽位、地图点位/连线、硬件型号字典、节点与容量 | 修改名称/点位、添加或复制节点、批量改规格、检查资源占用 |
| A04 租户与租赁订单 | 租户、客户地区、租赁规格、订单与合同段 | 维护样例客户、编排订单、设定价格与日期、查看关联影响 |
| A05 任务、实例与详情 | 任务、实例、调度日志、事件、近期 API 调用 | 成套编排运行样例、关联节点、编辑历史展示记录、执行模拟命令 |
| A06 遥测、用量与 Token | 当前监控值、近一小时曲线、边缘网络/心跳、资源用量段、Token 基线与每日计数 | 改样本、设置固定/波动模式、编辑来源、预览汇总 |
| A07 账单与告警 | 历史账单样例、费用快照、已收样例、告警与处理记录 | 在草稿中编排历史样例、检查账期、维护告警；运行期处理告警 |
| A08 策略文案与演示场景 | 四个固定模板、显示顺序、解释文字、场景参数与入口关联 | 编辑展示文案、预演场景、验证场景前提；不编辑算法规则 |

首版提供一个本地管理员，首次进入管理端必须设置本地密码；不开放手机号注册、实名认证或多用户审批。界面中展示的“管理员/租户”文字与本地管理入口的访问控制分开保存。

## 3. 一个草稿、一个应用动作

### 3.1 最小状态结构

| 状态 | 含义 |
|---|---|
| 已应用配置 | 当前展示端使用的品牌、文案、编号、地图点位和显示设置 |
| 当前演示运行态 | 节点、任务、实例、订单、用量、账单、告警、演示时钟及运行日志；由统一业务命令和唯一模拟时钟更新 |
| 当前方案初始数据 | 最近一次数据应用时确定的起点，用于“重新演示当前方案” |
| 单个草稿 | 从当前配置/数据复制而来的可恢复编辑副本，包含来源版本、编辑范围与未解决问题 |
| 应用前备份 | 场景应用或恢复前的完整业务状态和资产引用，默认保留最近 3 份；不建设复杂版本管理界面 |

所有业务实体继续使用稳定内部 id。新增 displayCode 用于对外展示编号；配置和运行数据分别带版本号，避免后台保存旧文案时顺带覆盖刚刚完成的运行操作。

### 3.2 编辑和预览流程

1. 管理员打开某项编辑时自动建立或恢复唯一草稿，不要求手动创建分支、提交审批或邀请协作者。
2. 合法和暂时未补齐的字段都可保存到草稿；草稿有本地自动保存状态，退出后可以继续。存在错误时允许保存草稿，但不能应用。
3. 预览使用与展示端相同的页面、字段格式化和计算规则，读取隔离的草稿数据；默认冻结草稿时钟，不消耗当前运行态或自动产生当前账单。
4. 每次编辑显示受到影响的页面及派生结果，例如改某订单单价后，同时预览订单金额、月度租金和未出账费用。
5. 主操作仅为“保存并应用”。点击后校验并准备资产；纯配置直接事务提交，结构替换先显示影响并确认，再生成一次备份和事务提交；成功后当前展示端读取新版本，保留原导航位置与能继续适用的筛选。
6. 失败时保留草稿和原展示版本，准确提示“草稿已保存但未应用”或“本次未能保存”，不能出现成功提示但重启后丢失。

### 3.3 两种应用方式

| 修改类别 | 应用方式 |
|---|---|
| 品牌、UiCopy、displayCode、机房/租户/型号显示名、地图点位、显示默认值、策略说明、未来遥测生成参数 | 校验配置基准后应用白名单差异，保留当前订单、账单、计量和模拟时间 |
| 节点容量、实体增删、客户业务归属、合同/任务/实例状态、历史用量/账单/Token/告警、历史曲线和演示日期 | 开始编辑前进入维护模式，暂停模拟与冲突业务动作；校验并确认后生成一次备份，再整体应用新的场景基线及运行态 |

修改类别由主进程根据字段决定，混合草稿整体按结构场景处理。纯配置编辑时原展示业务按钮可用；进入结构维护后暂停这些动作，页面仍可浏览。不得一边建立结构草稿、一边允许正式终止和迁移继续改变其基准。

结构应用前展示新增/删除记录、GPU/CPU、运行订单、账单与 Token 的变化摘要，明确替换演示进度。应用后换 runId 并保持暂停，管理员核对后继续。放弃结构编辑恢复进入前的播放状态；重启应用后维护状态和已保存草稿仍在。

普通业务动作以 businessRevision 检查并发，纯计量使用 runtimeRevision 更新快照，配置以 configRevision 保护。详细矩阵见 LOCAL_DATA，不用每秒变化的计量版本阻止普通按钮。

## 4. UiCopy 文案键注册表

### 4.1 必须登记的文案范围

所有固定可见文字从注册表读取，不散落成只能改源码的常量。注册表至少覆盖：

| 分组 | 覆盖内容 | 键示例 |
|---|---|---|
| 系统与导航 | 平台标题、窗口/页面标题、主导航、三个调度子导航、演示环境字样 | app.platformName、nav.overview、nav.scheduling.tasks |
| 首页指标与图表 | 七卡标题、已分配/空闲等辅助标签、地图标题、资源水位标题、三条指标名称、图例 | overview.kpi.gpu.title、overview.map.title、overview.water.memory |
| 各页与各表 | 八页标题、九张主表表头、详情附属表头、分区标题 | table.orders.columns.monthlyPrice、table.nodes.columns.model |
| 筛选与输入 | 筛选标签、搜索占位、全部选项、日期提示、格式提示 | filter.tenant.label、filter.keyword.placeholder |
| 状态与业务词 | 节点/任务/实例/订单/账单/告警状态显示词、地区及类型的显示名 | state.task.running、state.alert.processed、enum.region.overseas |
| 操作与确认 | 调度、暂停、恢复、重试、迁移、续租、终止、导出、确认/忽略、确认框提示 | action.task.dispatch、dialog.order.terminate.message |
| 抽屉与日志 | 节点/实例/订单详情标题、页签、属性名、时间线阶段名、格式化日志模板 | drawer.instance.events、log.schedule.filtered |
| 空态与反馈 | 没有结果、无关联实例、没有调用记录、保存成功/失败、校验反馈 | empty.table.noResults、feedback.apply.failed |
| 公共显示 | 分页文案、刷新文案、帮助提示、单位旁解释 | common.refresh.label、help.token.cumulative |

注册项保存：稳定 key、所属模块、后台可读名称、默认中文、当前覆盖值、长度限制、允许的占位变量、必要的语义说明。后台支持按当前文字/默认文字/模块搜索，普通用户无需知道 key 才能编辑。

### 4.2 文案编辑约束

- 文案为纯文本和受控占位变量，不执行脚本、不把任意 HTML 注入界面。
- 类似“终止 {orderCode} 将释放 {gpuCards} 张卡”的变量必须有效；必要变量丢失或拼错时不能应用。
- 状态显示词可以改为等义表达，底层 running/terminated 等枚举和状态颜色不变；不能将“终止”改成意味着继续运行的状态。
- 金额仍为人民币元，用量仍遵循卡·天/卡·月或算力单元·天；可改解释文案，不把单位名称换成美元来冒充币种转换。
- 四策略说明必须与只读的实际生效规则一致，不能宣称新增了真实迁移、实时调度或外部接口。
- 允许恢复某一项或某个模块的默认文案；不因此清空业务数据。
- 不允许隐藏或移除七卡、九表的必需字段来规避信息覆盖。

### 4.3 品牌与显示配置

可以编辑平台名称、Logo、演示租户显示名、角色显示文字、环境标记、地图区标题、刷新默认值、常规表格默认分页大小与默认排序。

Logo 以本地图片导入，首版支持 PNG/JPG/WebP；文件复制到本地受管理资产目录，不能只保存原始桌面文件路径。保留批准布局的尺寸边界，提供适配预览，不允许图片撑破顶部栏。字体、地图、图标等运行必需资源本地随程序提供，不依赖在线地址。

刷新选项仍为 10/30/60 秒，默认 30 秒；第一页首页仍以四行节点表为视觉默认。可调显示默认值不能移除分页、搜索或排序能力。

## 5. displayCode 与关联关系

所有会出现在列表、抽屉、地图提示、日志或导出中的业务编号，均提供可编辑的 displayCode。覆盖节点、任务、实例、订单、账单、策略；后台租户、用量段、告警等在需要可见编号时也使用同一方式。

- id 是内部稳定键，创建后不修改；关联仍保存 nodeId、taskId、orderId、tenantId 等内部 id。
- displayCode 是字符串，允许修改为客户想展示的编号，不能为空，同一实体类型内不得重复；历史记录中的同类编号也参与唯一性检查。
- 新建时自动给出默认编号，管理员可以修改；复制对象必须生成新 id 和不冲突的新 displayCode。
- 修改节点 displayCode 后，首页、监控、任务/实例详情、订单绑定、告警和 CSV 中的同一节点同步更新。
- 结构化运行日志通过关联 id 和模板参数渲染当前可见编号；草稿中的自定义历史说明可单独编辑。禁止在所有自由文本中做粗暴字符串替换。
- 界面需要同时显示订单与任务编号时标明类型，不能因两个类型的编号类似而错误关联。
- 不开放任意修改外键字符串的输入框；关系通过下拉、搜索选择或编排向导维护。

## 6. 所有展示字段的后台编辑矩阵

下列每一类字段必须有可发现的表单入口。“来源计算”意味着管理员可编辑来源并立刻看到预览，不意味着该信息无法调整；固定语义和算法控制项另行明确标出。

### 6.1 V01：七个指标卡、3D 地图与节点表

| 展示字段/内容 | 后台入口与可编辑来源 | 联动或约束 |
|---|---|---|
| 总 GPU / 已分配 / 空闲 | A03 节点容量；A05 实例资源预留 | 总量汇总节点 gpuCards，已分配汇总 allocationHeld，空闲相减；不保存三套手填总数 |
| 总 CPU / 已用 / 空闲 | A03 CPU 容量；A05 CPU 配额 | 首页“已用”仍表示分配核数，不等同于遥测使用率 |
| 总内存 / 总存储 | A03 各节点 memoryGB/storageGB | 十进制 GB 汇总后格式化为 TB，不能只改首页数字 |
| 在线节点 / 总数 | A03 节点记录及在线状态 | abnormal 但有心跳仍按现规则计在线；offline 不计在线 |
| 当日 Token / 累计 Token | A06 Token 基线、日期计数、输入/输出计数与速率 | 当日和累计从同一批计量记录生成；不得累计小于当日 |
| 当前在租月度总租金 | A04 有效订单、数量、单位月价、激活/结束时间及状态 | 只汇总当前有效中心租赁；X1 和中心自营 Token 不计租金 |
| 地图名称、图例、点位标签 | A02 UiCopy；A03 机房显示名、点位坐标、标签偏移 | 仍为批准的 3D 地图，不替换布局或地图边界 |
| 地图点位和连接弧线 | A03 稳定 siteId/nodeId 引用、经纬度、连线端点、受控样式 | 节点数/卡数随资源变化；不允许输入与节点表矛盾的机房统计数字 |
| 三个环图与对应趋势线 | A06 各节点有效遥测与时间序列 | 按现有权重计算；环图当前值与趋势末点一致 |
| 节点ID | A03 node.displayCode | 各页关联同步 |
| 机房 | A03 node.siteId 与 Site 显示名 | X1 必须归属 edge 槽位 |
| GPU型号 | A03 型号字典/节点型号；X1 的 chipModel | X1 型号未指定时显示“边缘算力芯片” |
| 卡数 | A03 node.capacity.gpuCards | X1 固定 0，展示“—” |
| 已分配卡数 | A05 当前实例配额与 allocationHeld | 来源计算，不允许超过节点容量 |
| GPU利用率 | A06 节点当前遥测或手工曲线末值 | 0—100；无适用 GPU 时为不适用 |
| 状态 | A03 草稿在线状态编排；运行中通过节点模拟命令 | 设置离线时同步解释实例/订单异常及心跳，不只换颜色 |

每个派生指标在后台提供“编辑来源”入口及分项列表，例如月租可逐笔查看构成订单，GPU 已分配可逐实例查看占用。无需让管理员通过改 JSON 才能改变某个指标。

### 6.2 V02：任务队列十个原文字段及操作

| 展示字段/内容 | 可编辑来源 | 联动或约束 |
|---|---|---|
| 任务ID | A05 Task.displayCode | 稳定 taskId 不变 |
| 任务类型 | A05 taskType/businessType | 保留租赁实例、Token 推理、边缘算力三类语义 |
| 优先级 | A05 任务优先级 | 可编排样例高/中/低，不覆盖租赁不能被抢占等硬约束 |
| 需求规格 | A05 GPU 型号/卡数、CPU/内存、边缘单元、实例形态、回落规格 | 结构化编辑并校验，不用一段自由文本代替实际规格 |
| 目标机房偏好 | A05 preferredSiteId；边缘 preferredNodeId | 租赁不得选边缘目标；地图和筛选同步显示新名称 |
| 客户地区 | A04 关联租户的 customerRegion | 从租户读取，不在任务上保存一份矛盾地区 |

| 创建时间 | A05 草稿时间字段 | 不晚于演示时钟，历史时间链自洽 |

| 调度日志 | A05 预置历史日志；运行日志模板与命令结果 | 节点匹配、资源过滤、失败原因均能编辑样例来源或由命令生成 |

### 6.3 V03：四个固定策略模板七个字段

## 7. 地图、遥测和趋势的维护方式

### 7.1 地图点位编辑

- 出厂仍包含三个中心机房和一个边缘分类槽位；稳定 siteId/kind 不变，机房显示名、地图坐标、标签偏移、节点名称和数据可以修改。
- 中心槽位不能改成边缘，边缘槽位不能改成可租中心。四个基础槽位不提供删除，避免规则和导航语义失效；可在槽位下新增/复制节点。
- 边缘类别可配置多个 X1 示意点；点位可以关联具体设备或聚合组，统计均来自真实关联的演示节点。
- 连线选择已有端点，支持方向、是否显示、受控颜色/动效强度；不得悬挂不存在的点。
- 坐标使用统一投影，省面、节点和连线一起转换；落在当前地图不可见范围的点位不能无提示应用。
- 图层顺序、地图行政轮廓、整体倾角/挤出风格保持已批准方案，不将 CMS 扩为地图制作工具。
- 内蒙古出厂位置仍为区域示意；管理员自填更具体位置属于自己的演示数据，程序不宣称已核实真实机房地址。

### 7.2 当前指标与曲线模式

未来生成目标值、幅度、种子和 Token 速率属于配置，从应用时刻起生效，不回写之前曲线。替换当前或历史样本、历史上报时间、当日或累计基数属于结构维护。进入同一编辑页面不代表所有字段使用同一种应用方式。

每个节点的遥测可选择：固定值、带固定种子的轻微波动、手工样本序列。管理端提供百分比/已用容量联动输入、温度、最后上报时间及曲线预览。

- 手工历史序列在结构维护模式中编辑，采用统一时间窗口和顺序；应用新场景后末点成为该场景当前值；不能环图是 66% 而对应趋势末点是 20%。
- 近一小时曲线默认按分钟桶保留 60 个点；10/30/60 秒刷新更新对应分钟桶，不把 60 点错误缩成最近 10 分钟或 30 分钟。当前分钟使用最新有效值，以便与当前环图对应。
- 内存和存储以已用容量及总容量为来源；输入百分比时转换为同一已用容量字段，不同时保存两套矛盾答案。
- 首页三条聚合趋势由节点序列按相同时间桶计算，不能另造三套总览随机线。
- 修改节点容量时重新检查各个样本是否越界，不能让内存用量超过新容量。
- 离线节点最后上报时间停止推进；固定模式只固定数值，不冒充离线节点的新心跳。
- 一个本地模拟时钟负责推进所有窗口的数据；两个窗口同时打开不会使 Token 翻倍。
- 程序完全退出后不继续计量；重开从已保存时间继续，不补算离线期间。

## 8. 草稿数据编辑与运行命令必须分开

| 需求 | 草稿中的样例编排 | 当前运行态中的动作 |
|---|---|---|
| 展示一个运行中的租赁订单 | 成套选择租户、订单、任务、节点、配额、实例与起止时间，并生成一致用量段 | 调度已有待调度订单 |
| 展示暂停实例 | 保存原状态、保留 allocationHeld、设置暂停区间，Token 停在暂停点 | 暂停命令先结算旧区间，再同步任务/实例，不释放资源 |
| 展示节点离线 | 修改节点/心跳，同时编排关联异常订单、失败任务、错误实例和告警 | 节点模拟故障命令一次性改变上述实体 |
| 更改绑定节点 | 在新样例中整体调整分配和用量段并校验 | 迁移命令关闭旧段、保留历史、占用新节点 |
| 更改订单金额 | 编辑草稿合同来源或历史费用样例，重算派生金额 | 续租只追加合同段；终止只结算未出账区间 |
| 更改历史记录 | 草稿中编辑/替换历史样例，应用后成为新场景 | 原运行记录保留；业务命令生成新事件，不原地重写旧记录 |

成套编辑向导是管理能力的必要组成：不能要求普通用户分别找到六张表手动凑出一个合法运行订单。首版继续采用一笔租赁订单、一项租赁任务、一个当前实例；整机/裸金属单笔数量固定一台，GPU 订单数量是单节点上的卡数。多节点整单编排不默认加入本次范围。

所有运行命令仍调用同一套业务规则：租赁优先、边缘回落、空闲填充、迁移、暂停/恢复、终止和续租不能在管理端另写一套。任务“调度中”、实例“迁移中”保持命令执行过程中的临时忙碌态，不允许长期保存成一个半完成样例。

日志区分“草稿预置记录”和“本轮命令生成记录”。管理端可以编排前者；运行中不能把刚失败的调度日志随意改成成功，却让实例保持失败。若确需换整个故事，编辑新草稿并应用。

## 9. 历史账单如何既可演示编辑，又不破坏快照规则

### 9.1 当前运行态

- 已出账的金额、价格、数量、账期、已收金额和结算时间保持快照语义，不因修改当前订单、终止实例或调整硬件价格被反算。
- 新增后台不提供一个针对已支付账单的“直接改金额并保存到当前演示”按钮。
- 演示时钟可以使未支付账单达到逾期条件，但不会自动产生收款或改变已支付金额。
- 出账、续租和终止沿用原 30 天规则与一次舍入规则；重复命令不重复出账。

### 9.2 历史样例编辑入口

管理员可在 A07 选择“编辑历史样例”，进入当前草稿，修改可见账单编号、关联租户/订单、账期、费用行价量、样例已收金额、到期日和结算时间。应收金额由费用行重新计算，状态由价款与时间校验。

应用前必须核对：

1. 关联的是中心租赁订单，非 X1 或自营 Token 任务。
2. 同一订单的出账期间不重复覆盖，时间区间有效。
3. 应收等于费用行合计；已收不为负且不超过应收；已支付状态与已收、结算时间一致。
4. 修改合同来源不会无提示地重算所有已出账记录。若管理员希望改历史账单，必须在该草稿中显式选中相应样例编辑。
5. 保存并应用时生成新的演示起点，并保留应用前完整备份；不把这次样例重编排伪装成原历史账单从未改变。

因此用户仍能控制展示端的每一笔账单内容，但必须通过“编辑来源—校验—应用新样例”路径，不损坏本轮运行的快照语义。没有真实财务冲账、退款、收款或审计系统承诺。

## 10. 字段联动、删除与应用校验

### 10.1 必须阻止应用的数据错误

| 校验 | 必须成立的规则 |
|---|---|
| 编号与关联 | id 稳定且唯一，displayCode 满足同类唯一；全部外键存在 |
| 节点容量 | GPU/CPU/边缘单元为非负有效数量；资源预留不超过节点容量 |
| 资源占用 | 当前分配从 allocationHeld 计算，终止实例不继续占用；暂停/离线保留实例仍占用 |
| 一单一实例 | 一笔租赁订单只有一个当前租赁任务及实例；同一任务不产生两个未结束实例 |
| 租户一致性 | 订单、任务、实例、用量、账单的客户归属不矛盾 |
| 租赁范围 | 租赁只在中心，不能绑定 X1；裸金属/整机独占对应节点 |
| 边缘限制 | X1 orderId 为空，gpuCards 为 0，使用 edgeUnits，设备租金/应收始终为 0 |
| Token | 输入/输出为有效非负整数；历史与日计数不重复，累计不小于当日；新实例不继承无关历史产出 |
| 时间 | 合同、使用段、账期、日志、处理时间顺序有效，不出现结束早于开始 |
| 用量段 | 同实例最多一个未闭合段，迁移/暂停切段不重叠；历史按原节点保留 |
| 账单 | 价量期间可复算、合计正确、出账不重复、已收/状态/日期一致 |
| 遥测 | 百分比范围有效，时间有序，容量/当前值/趋势末点不矛盾 |
| 地图与资产 | 点位可见、连线端点存在，Logo/图片在受管理本地目录可读取 |
| 策略 | 四个内部模板齐全；算法启用、优先级与固定规则不被文案字段覆盖 |
| 文案 | 必需文案非空，变量合法；不以可编辑标签改变业务单位或状态含义 |

保存草稿允许暂时不完整；应用失败时按“模块—记录—字段—原因”定位，可以直接跳回编辑，不弹一个笼统的“数据错误”。

### 10.2 删除关联检查

- 删除只默认发生在草稿；当前运行中用终止、结束或处理动作，不能把运行实体直接删掉。
- 点击删除先展示关联数量及清单：节点关联实例/用量/告警，租户关联订单/任务/账单，订单关联任务/实例/合同/账单，实例关联用量/Token/API/事件。
- 存在引用时默认阻止单条删除，提供“查看引用”及“调整引用/移除整套样例”。不做静默级联删除。
- “移除整套样例”只在草稿中可用，列出会被移除的所有相关对象；共享租户、节点或被其他样例引用的对象不能连带删除。
- 历史账单、用量和 Token 不能因删除一个当前实例而无提示消失。为改变历史展示，需要显式移除对应历史样例并重新校验汇总。
- 四个基础机房槽位、四个策略槽位、固定业务枚举和 UiCopy 必需键不能删除。
- 删除图片前检查 Logo/节点/页面等引用；仍被当前应用版本或应用前备份使用的文件不立即物理删除。

## 11. 导入、导出、恢复与本地保存

### 11.1 完整数据包

统一导出 .caas.json 内容包，包含已发布配置、场景基线、当前运行态、已保存草稿和自定义素材；本地管理员、密码哈希、盐和会话一律排除。导出页面说明未应用草稿也在包中。格式、图片大小与完整性默认值见 LOCAL_DATA 第 6 节。

导入先在隔离临时区校验并预览，不立即改动正式数据或已有草稿。预览列出资源、账单、Token、素材与草稿变化；确认后暂停、备份、原子应用新内容。导入的草稿仍是未应用状态；目标电脑的本地密码不变化。损坏文件、未知版本或非法正式数据不得污染当前库。

内容包用于备份和跨电脑迁移，不建立后续自动同步。初版采用整套替换，不做增量合并。CSV 仍用于计费报表，不用于恢复完整业务关系。所有注册字段必须有表单入口，不能只提供一个 JSON 文本框让用户自行凑数据。

### 11.2 恢复动作

| 动作 | 结果 |
|---|---|
| 放弃当前草稿 | 放弃未应用编辑；若为结构维护，退出维护并恢复此前播放状态 |
| 重置本轮演示 | 从当前已发布场景基线开始，保留 CMS 配置和基线历史，换新 runId |
| 恢复备份 | 预览选定内容备份、保护当前内容后恢复；目标机账号保持 |
| 恢复出厂内容 | 备份并确认后恢复随包配置与标准种子，清理草稿，保留账号与程序身份 |

恢复或场景替换后默认暂停，管理员核对后继续；重置本轮保留此前播放状态。结构维护期间不允许展示端绕过维护锁执行重置。

### 11.3 保存与异常

- 正常保存写入本机可写用户数据目录，不要求用户修改 exe 或在安装目录手工编辑文件。
- 单次应用包括配置、业务数据、版本与资产引用的完整提交；任何一步失败均不切换展示端版本。
- 程序崩溃后可恢复最后成功应用的状态和最后成功保存的草稿，不把不完整写入当成有效状态。
- 本地存储不可写、磁盘空间不足或备份/图片复制失败时明确反馈，保留旧版本；不只显示操作成功。
- 两个窗口不各自保存全量快照；通过同一个本地写入入口提交差异或业务命令，防止互相覆盖。
- 完全离线启动、编辑、预览、应用、导入导出均可工作，不要求在线验证码、云许可证检查或远端地图资源。

## 12. 最小验收清单

### 12.1 编辑覆盖

- [ ] 无需改代码，能在管理端修改标题、Logo、六个导航、三个子导航、七卡标题、九表表头、状态词、按钮、筛选提示、空状态和主要抽屉文案。
- [ ] 所有对外编号可改 displayCode，改节点编号后所有相关列表、详情、日志/导出同步，内部引用不丢。
- [ ] 能编辑机房名、地图点位和连线；批准的 3D 地图与七卡/三环图/底表布局保持。
- [ ] 能调整节点容量、实例分配和订单来源价，使首页 GPU/CPU/月租等汇总随之改变；不存在必须改源码的硬编码 KPI。
- [ ] 能编辑 Token 历史和当日来源、遥测曲线、API 记录、网络心跳，所有对应详情可见变化。
- [ ] 八视图九核心表的全部业务字段均有本规格所列入口或“编辑来源”入口。
- [ ] 四策略名称、说明、显示顺序可改；实际优先级与启用清楚标为受约束项，不出现假开关。

### 12.2 一致性与业务操作

- [ ] 模拟运行订单可通过后台成套编排，不要求用户手工补齐多个关联表。
- [ ] 展示端原调度、暂停/恢复、终止、迁移、续租、告警处理操作仍有效。
- [ ] 任意编辑都不能给 X1 增加租赁订单、GPU 卡或设备租金。
- [ ] 资源超卖、断链、重叠用量段、重复出账和不合法时间能阻止应用并定位问题。
- [ ] 原运行态中已支付账单不被订单变动反算；历史样例可以在草稿中改来源，应用为新场景后展示新内容。
- [ ] 删除有引用记录会提示关联，不会悄悄删除历史账单、Token 或无关租户。

### 12.3 草稿、应用与离线恢复

- [ ] 只有一个可恢复草稿，预览不污染展示端；一个“保存并应用”动作完成有效切换。
- [ ] 只改文案并应用，不回滚正在展示的订单状态与计量。
- [ ] 应用业务数据前明确显示场景重载影响，并备份当前运行态；展示端不会出现半套新数据。
- [ ] 两个窗口同时打开时只有一个模拟时钟，Token 和费用不会翻倍。
- [ ] 断网环境下，改文案、数据和 Logo 后退出重开仍保存；故意制造保存失败不会出现假成功。
- [ ] 完整导出包可在另一台电脑预览并恢复，显示和数据一致；之后两台电脑修改互不自动同步。
- [ ] 重新演示当前方案保留自定义品牌；恢复出厂先备份并确认影响；恢复备份可回到之前内容。

## 13. 给实施代理的最终边界

这是“固定 3D 展示布局 + 全覆盖本地内容与数据维护 + 真实磁盘保存 + 可交互模拟业务”的桌面升级。不要缩成只有产品名称/价格可改的简易 CMS，也不要扩成自由页面设计器、真实云算力管理或跨电脑同步平台。

实现顺序建议：先接通一个真实本地草稿/应用闭环，再登记 UiCopy 与 displayCode，随后实现基础实体及成套样例编辑，最后覆盖趋势/历史记录、完整包迁移和删除校验。每一步都用批准的展示端立即验证，避免最后发现某些可见文字或数值仍只能改源码。

## 14 受控文案与显示元数据

UiCopy 的语义保持由后台显示固定原含义提示和人工验收约束，程序校验必填、长度和占位变量，不建设自然语言审查服务。原生窗口操作、数据删除影响和保存失败等必须保留准确行为，不能因改文案而省掉真实校验。

entityPresentation 覆盖层存放按实体类型与内部 id 索引的 displayCode、显示名等元数据；selector 优先读覆盖值，再读实体默认值。内部业务枚举和 ID 保持稳定。过时实体可保留历史显示映射；对正式发布数据，不能引用未知对象或产生同类重复显示编号。

业务菜单、卡槽、必需列、状态颜色含义与币种不是自由布局编辑项。exe 图标、安装名称、appId、发布者签名等包级元数据需要构建配置，不由内容后台即时改写。

## 15 从配置草稿进入结构维护

一个已存在的配置草稿首次加入结构字段时，主进程先结算并进入维护。保留已经编辑的配置差异，但结构部分必须从此时最新已提交的运行状态建立，不沿用打开配置页面时的旧快照。维护后更新 sourceRunId/sourceBusinessRevision，再继续编辑。纯配置应用不自动建立内容备份；结构应用、导入、恢复备份和恢复出厂在确认后、替换前生成一次自动内容备份。
