# CaaS 桌面展示端逐页面功能与验收清单

版本 v2.0。本文件保留用户原始八视图、九主表及全部业务演示动作，运行在 Electron 展示窗口。管理后台字段编辑见 ADMIN；SQLite 保存、单草稿、维护模式、同步与恢复见 LOCAL_DATA。所有标为建议或待确认的旧条目，已由 PROJECT_PLAN、DATA_RULES 或 LOCAL_DATA 定义的，直接按统一决定执行。

## 1 本版交付边界

- 展示窗口默认打开算力总览，后台管理另开一个受控窗口；全部数据和资源在本机可用。
- 所有业务动作通过主进程领域服务执行，重启客户端后保存；不将 localStorage 作为业务数据库。
- 管理端可编辑文案、实体、模拟遥测和场景；派生值通过共同 selector 联动，编辑入口与可计算约束见 ADMIN。
- 展示页继续操作调度、暂停、迁移、终止、续租和告警，不能因为增加 CMS 就改成只能看的大屏。
- 本地管理保存属于首版本次范围；真实设备接入、线上认证和支付不自动纳入。

## 1.1 机房名称和业务分类

本文件中的南宁智算中心、成都智算中心、内蒙古机房和边缘站点均为出厂默认显示名。管理端可更改显示名；实际地图、筛选、表格、详情、日志和 CSV 统一读取已发布名称。下表列举默认文案时不意味着把字符串写死在代码中。

三个中心槽位、一个边缘分类槽位及其内部 siteId/kind 保持稳定。租赁资格根据这些内部身份与 kind 判断，不能通过比较“边缘站点”四个中文字判断；X1 永远归属边缘分类且无租赁与租金。

### 2.2 外层布局与顶部栏

**【明确要求】**

- 左侧固定导航包含且至少完整展示：算力总览、调度中心、资源监控、租赁订单、计量计费、告警中心。
- 调度中心提供任务队列、调度策略配置、任务实例管理三个子视图。
- 顶部栏包含平台名称、当前租户/角色、刷新频率选择、手动刷新按钮。
- 刷新频率选项为 10s、30s、60s，默认 30s。
- 右侧内容区跟随导航切换，当前导航有明确选中态。

**【已确认设计】**

- 首页以交付包中的 reference/ui-approved.png 为视觉基准，参见[已批准的首页设计](../reference/ui-approved.png)。
- 保留深蓝商务科技风、清晰卡片、固定侧栏、顶部七个指标卡、大面积 3D 中国地图、右侧三个独立资源水位环图和底部节点表。
- 右侧三组资源水位按批准图纵向排列，每组包括环图、指标名称和简洁趋势线；趋势线与对应模拟指标保持一致。
- 中国地图是首页主视觉，必须体现可辨认的立体厚度、机房节点及空间层次。不能擅自替换成柱状图、普通平面地图或一张与数据无关的背景。
- 原需求允许地图或柱状图，但本轮用户已经选定 3D 地图；后续开发以这个更新后的约束为准。
- 地图上机房名称与正文使用真实网页文字或同等清晰的文本层，不能把生成图中的乱码、错字或数字直接当成业务内容。
- 底部首页节点表建议首屏显示四行，把主要视觉空间留给地图；其他页面可采用常规数据表密度。

**主视觉验收描述：** 深蓝后台保持固定侧栏与七张顶部指标卡；中央以发光侧壁、机房节点和弧线构成立体中国地图。右侧纵排三组环图及趋势线，底部保留四行节点表；文字清楚，主次分明，不得改成柱状图。

**【建议默认】**

- 以 1920×1080 设计比例为参考，并保证常见桌面窗口下可用；较窄窗口允许表格横向滚动，不能删掉必需字段。
- 顶部租户与角色为演示身份展示；本地管理端另设管理员登录，不等于真实客户租户隔离。
- 演示设置中的“重置本轮演示”从当前发布基线复位，保留 CMS 内容。管理端“恢复出厂内容”恢复标准种子和默认展示配置，先备份并确认影响，保留本地管理员。
- 页面具有加载、空结果和错误展示；状态变化使用明确反馈，但不妨碍继续演示。

### 2.4 所有表格的通用要求

**【明确要求】** 所有表格支持分页、按列排序、关键字搜索。

**【建议默认及验收方式】**

- 搜索和各筛选条件按“同时满足”组合；改变筛选后回到第一页。
- 关键字搜索覆盖每张表最主要的业务 ID、名称及可识别文本；本文件在各页补充最低覆盖字段。
- 数值按数值排序，时间按时间排序；不允许把 100 排在 20 前面的字符串排序错误。
- 操作按钮列、纯装饰列无需排序；复合字段可明确选择一个主排序字段，例如“GPU 型号&卡数”以卡数为主。
- 常规列表建议默认每页 10 条，并允许切换 10/20/50；首页四行样式可使用独立的默认分页大小。
- 空字段显示“—”；只有确实为零的指标才显示 0。边缘设备不适用的租赁金额不能被展示成一笔“免费租赁”。
- 分页不改变统计总数；切换页面不丢失已完成的业务操作。
- 详情中的附属记录表至少能查找和浏览完整记录；记录数超过展示容量时同样提供分页或等价的分页控件。

### 2.5 刷新、颜色、单位和时间

**【明确要求】**

- 自动刷新适用页面：算力总览、资源监控、调度中心的任务队列和任务实例管理。
- 默认 30s，可切换 10s/30s/60s；保留手动刷新按钮。
- 在线/运行中为绿色，空闲为蓝色，异常/离线为红色，警告为橙色；边缘站点离线同样为红色。
- 金额统一“元”；资源用量统一“卡·天”或“卡·月”；边缘算力用量为“算力单元·天”。

**【建议默认】**

- 四个自动刷新页面共用一个刷新设置，不在反复切换导航后叠加多个计时器。
- 未要求自动刷新的页面可在进入时读取最新共享状态；手动刷新读取当前状态，不自动创建新订单或新账单。
- 刷新可以更新模拟利用率、曲线和心跳；不得通过各页独立随机数破坏总量、分配量和关联关系。
- 离线节点的最后上报时间应停止前进，不能每次刷新都显示刚刚上报。
- 表格时间统一显示为 YYYY-MM-DD HH:mm:ss，界面统一使用一个演示时区和演示时钟；建议 Asia/Shanghai。
- 金额显示两位小数，底层计算使用统一精度规则；显示格式不能替代计算。
- 终止/已结束状态可用中性灰；提示级告警可用蓝色。颜色之外保留文字状态。

## 3. V01 算力总览

### 3.1 顶部七个指标卡

| 卡片 | 明确要求的内容 | 演示计算与展示约束 |
|---|---|---|
| 1 | 总 GPU 卡数 / 已分配 / 空闲 | GPU 总卡数 = 已分配卡数 + 空闲卡数；不把没有 GPU 的边缘算力芯片强行计作 GPU 卡 |
| 2 | 总 CPU 核数 / 已用 / 空闲 | 三者口径一致；可按已分配 CPU 核数展示“已用”，不能把百分比与核数相加 |
| 3 | 总内存、总存储 | 两个容量值放在同一张卡中，单位清楚 |
| 4 | 节点在线数 / 总数 | 覆盖南宁、成都、内蒙古及边缘站点，不遗漏 X1 |
| 5 | 当日 Token 总产量 | 来自统一 Token 产出记录或统一聚合状态 |
| 6 | 累计 Token 总产量 | 与当日值分成独立卡；同一截止时刻累计值不得小于当日值 |
| 7 | 当前在租算力月度总租金 | 只汇总三大中心机房的有效租赁；不把 X1、Token 采购金额或历史已结束订单加入 |

【待确认口径】“已用 CPU”是分配核数还是实时等效使用核数，原文没有定义；建议首页使用分配核数，并在字段说明中固定。节点异常时仍可能存在有效租约，异常是否停止租金不能由页面颜色隐式决定。

### 3.2 中部资源分布与资源水位

- 【已确认设计】使用大面积 3D 中国地图，三大机房节点正确标注为南宁智算中心、成都智算中心、内蒙古机房，同时区分边缘站点。
- 【明确要求】按地域/机房展示节点数和卡数。可以在节点标签、悬浮提示或地图旁的简洁摘要中显示，而不是只做三个发光点。
- 【建议默认】南宁和成都按城市位置标注；内蒙古仅按区域示意，不杜撰未提供的机房城市。边缘站点使用不同大小或样式的小节点与图例。
- 【明确要求】右侧提供 GPU 利用率、内存利用率、存储利用率三个独立环图。GPU 利用率不等同于 GPU 分配比例。
- 【建议默认】点击机房节点可以联动筛选底部节点表；这属于演示增强，不是原文明确规定的地图操作。
- 地图的节点数/卡数、指标卡总数和节点数据必须来自同一来源。

### 3.3 节点列表

**字段完整顺序：** 节点ID｜机房｜GPU型号｜卡数｜已分配卡数｜GPU利用率｜状态。

- 机房筛选包含四个标准机房选项。
- X1 的机房列显示边缘分类的已发布名称，默认“边缘站点”，型号列显示边缘算力芯片型号。
- 【待确认口径】原文未提供 X1 真实芯片型号。演示可使用“边缘算力芯片”占位；不能编造真实硬件型号。没有 GPU 卡概念的字段显示“—”，并从 GPU 卡总数统计中排除。
- 关键字最低搜索范围：节点 ID、机房、型号。
- 【建议默认】点击节点 ID 复用资源监控的节点详情抽屉，不新增独立详情页。

## 4. V02 调度中心：任务队列

### 4.1 筛选条件

| 条件 | 明确要求 |
|---|---|
| 任务类型 | 租赁实例、Token推理任务、边缘算力任务 |
| 任务优先级 | 原文未规定枚举；建议高、中、低 |
| 状态 | 待调度、调度中、运行中、失败、终止 |
| 机房 | 南宁智算中心、成都智算中心、内蒙古机房、边缘站点 |
| GPU 型号 | 从演示资源字典生成 |
| 时间范围 | 建议按任务创建时间筛选 |

原文另给出客户地区下拉选项“海外客户、国内客户”。为完整覆盖要求，任务队列提供客户地区筛选；没有客户归属的系统任务保留“—”，可通过“全部”查看。

### 4.2 表格字段

任务ID｜任务类型｜优先级｜需求规格（GPU卡数/型号/实例类型：裸金属/边缘实例）｜目标机房偏好｜客户地区｜任务来源（租户订单/系统自动任务）｜创建时间｜状态｜调度日志。

- 关键字最低搜索范围：任务 ID、型号、目标机房、关联订单 ID（即使在详情中呈现）。
- 需求规格是结构化数据的展示，不应把整段字符串作为实际容量判断依据。
- 租赁任务不能把边缘站点作为可执行目标。

### 4.3 操作与演示状态变化

**【明确要求】** 手动调度、暂停、终止、重试、查看调度日志。

| 操作 | 建议的有效对象 | 建议的演示结果 |
|---|---|---|
| 手动调度 | 待调度任务 | 进入调度中，再进入运行中或失败；成功时绑定资源并建立/更新实例 |
| 暂停 | 待调度或运行中任务；调度中禁用 | 保存原状态并暂停；运行实例保留资源、停止新增产出；恢复不重复分配 |
| 终止 | 尚未终止的任务 | 确认后进入终止；关联实例结束，释放原占用资源；涉及租赁时同步相关订单 |
| 重试 | 失败任务 | 保留历史日志，重新进入待调度/调度中；不能重复创建同一租赁订单 |
| 查看调度日志 | 所有任务 | 打开该任务真实对应的演示日志，而不是所有行同一个固定弹窗 |

【待确认口径】原文要求“暂停”，但状态枚举没有“已暂停”，也没有定义恢复操作。建议 首版 增加“已暂停”状态及对应筛选，并在暂停任务上把按钮变为“恢复”。这一补足必须在采用的演示约定中列出，不能默默声称原文已要求。

### 4.4 调度日志弹窗

**必须展示：** 节点匹配、资源过滤、失败原因。

【建议默认】以时间顺序显示：任务进入队列、读取策略、候选机房/节点、按类型与容量过滤、是否迁出 Token 任务、最终节点匹配、成功/失败结果。失败时给出明确理由，例如资源不足、目标节点离线或边缘站点不承接租赁。

- 展示任务 ID、执行时间、日志级别/阶段、日志内容。
- 重试后保留此前失败记录；可区分不同尝试。
- 模拟调度只操作共享演示状态，不调用真实调度系统。
- 操作成功不等于所有情况都必须调度成功；存在可解释、可重试的失败样例。

### 4.5 验收清单

- [ ] 所有筛选项和十个表格字段完整。
- [ ] 客户地区只有海外客户、国内客户两个业务选项，外加“全部”。

| 确认 | 将告警标为已处理，记录处理方式为确认、处理时间及演示操作者 |
| 忽略 | 将告警标为已处理，处理方式记录为忽略；保留原告警和可追溯信息 |
| 跳转节点 | 打开对应节点详情，或跳到资源监控并定位该节点 |
| 跳转实例 | 有有效实例关联时打开实例详情；无实例时隐藏或禁用该操作 |

- 确认/忽略告警不等于修复硬件，不应自动把离线节点改成在线。
- 已处理告警不应再次重复累计处理记录，除非明确提供重新打开功能；原文未要求该功能。
- 边缘离线告警使用红色；警告级使用橙色，文字级别仍需保留。
- 节点详情中的告警记录应同步显示最新处理结果。

### 10.3 验收清单

- [ ] 六个字段、六类告警、三级级别与两种处理状态完整。
- [ ] 有至少一条无实例 ID 的节点告警，且跳转不会报错。
- [ ] 确认与忽略可区分处理方式，但保持两态状态模型。
- [ ] 处理后当前列表与节点详情同步。
- [ ] 确认离线告警不会把节点自动修好。
- [ ] 可从告警定位正确节点和实例，返回后仍保留原列表上下文。

## 11. 全局业务约束与一致性验收

### 11.1 必须维持的关系

| 关系 | 必须成立的约束 |
|---|---|
| 订单与节点 | 租赁订单只能绑定南宁、成都、内蒙古中心机房；不绑定 X1 |
| 订单与任务 | 租赁任务来源为租户订单，能查到对应订单；系统推理任务可以没有订单 |
| 实例与节点 | 同一时刻实例的有效绑定明确；迁移完成后不同时占用两个节点 |
| 节点与总览 | 容量、已分配、空闲与首页汇总一致；占用不超过可分配容量 |
| 实例与用量 | 终止不会删除已发生用量；刷新不会重复记同一时间段 |
| 用量与账单 | 采用一致的资源单位、计价规则和账期，不能各页自行计算 |
| 边缘与租金 | 边缘仅产出 Token，不产生设备租赁与应收租金 |
| 告警与资源 | 告警关联的节点/实例可找到；处理告警不自动修复资源状态 |
| Token 产出 | 同一批产出不因跨机房迁移或刷新而重复累计 |
| 客户端本地持久化 | 刷新后保持有效状态、关联和日志；恢复初始数据后所有页面一并恢复 |

### 11.2 建议准备的完整演示场景

这些场景用于把原文业务说明变成可观察结果；场景控制入口属于建议增强，可以放在演示设置中，不必增加左侧业务导航。

| 场景 | 操作与预置条件 | 可观察的验收结果 |
|---|---|---|
| S01 初始全景 | 加载初始样例 | 八个视图可访问，七卡和 3D 地图完整，四类机房均存在 |
| S02 租赁优先 | 某中心节点正在跑 Token 推理，有一个待调度租赁任务 | 手动调度后该目标节点的 Token 任务迁出/重新排队，租赁实例运行；其他无关节点任务不被清空 |
| S03 资源不足 | 给定资源不足的任务 | 任务失败并有节点匹配、资源过滤与失败原因；重试保留历史日志 |
| S04 终止租赁 | 从订单入口终止有效租赁；一单一实例样例也可从实例入口演示 | 订单、任务、实例同步结束，节点释放；总览租金下降，历史用量不丢失；一单多实例的部分终止按单独约定处理 |
| S05 空闲填充 | 中心节点没有有效租赁且空闲 | 可演示其开始 Token 推理；收到租赁后让出资源 |
| S06 边缘回落 | X1 资源不足/过载，有可用中心节点 | 推理回落到中心裸金属，任务仍为推理，不创建 X1 租约或中心设备租金订单 |
| S07 实例迁移 | 选择一个有合法目标的实例 | 绑定节点与两端占用正确更新，详情事件记录迁移；无重复资源占用 |
| S08 告警处理 | 从边缘离线告警进入详情并确认/忽略 | 跳转正确、处理同步，离线节点仍保持离线直到另一个明确的模拟恢复事件 |
| S09 导出核对 | 使用跨多页的计费筛选结果导出 | CSV 行数等于全部匹配行，金额合计与页面一致，中文可读 |
| S10 刷新与保存 | 修改频率、完成操作、重启客户端 | 设置与业务状态保留，计时器不重复，数据不会重新随机生成 |
| S11 恢复样例 | 在演示设置确认恢复 | 运行实体和日志一起回到当前已发布基线；CMS 配置保留 |

### 11.3 建议的样例覆盖

- 四类机房必须都有节点；X1 有在线、离线或过载样例。
- 三类租赁资源都有订单，订单四种状态都有合理数据。
- 租赁、Token 推理、边缘算力三类任务都存在，且可看到成功和失败调度。
- 有运行中、已结束或异常实例，也有没有 API 调用的合理空态。
- 租赁与 Token 相关样例以海外客户居多，同时保留国内客户；不声称样例占比是真实经营数据。
- 用量包含中心租赁、中心推理和边缘产出，三者不会被混为同一种租金。
- 账单有待支付、已支付、逾期样例；告警覆盖六类，并包含无实例关联的记录。
- 可分页的主要业务表提供多于一个分页的数据量；四条固定策略不需要为了分页制造额外模板。

## 12. 开工前必须显式记录的口径与遗漏风险

| 风险或歧义 | 推荐处理 |
|---|---|
| 原文明确仅用于客户演示，容易被解读成真实调度平台 | v2 保留模拟业务，增加真实本地 CMS 与 SQLite 保存；真实设备接入继续单列 |
| 地图曾允许柱状图，但用户后续已选 3D 地图 | 以最新选择为准，禁止自动降级；发现性能或素材问题先报告，再讨论同视觉方向的实现方案 |
| 暂停没有状态和恢复定义 | 采用“已暂停 + 恢复”的建议补足并记录；不能按钮有反应但业务毫无变化 |
| 告警忽略与两态状态模型不一致 | 状态保留未处理/已处理，另外记录确认/忽略处理方式 |
| 策略表有操作列，容易扩成复杂策略配置 | 展示端四模板查看；管理端编辑说明和显示顺序，算法类型和启用含义保持固定 |
| 裸金属与整机分类有重叠，计价单位未定义 | 保留原始业务分类，使用不同演示 SKU/规格；明确每笔订单的租金对应单位 |
| 月租金、日计费、续租、提前终止的金额规则未定义 | 整个项目只有一套演示计费规则；日折算、月周期、取整、终止结算由统一章节规定 |
| GPU 卡用量与整机设备租金不在同一计价维度 | 展示用量与计价数量分别保存，避免用卡·天直接乘设备月租金 |
| Token 产出、消耗和采购背景混用 | 字段与汇总口径分别定义；Token 采购系统不自动加入 首版 |
| 海外客户为主被扩成多语言、多币种和跨境支付 | 只做客户地区与演示样例占比；金额按原文统一元 |
| 顶部租户/角色被扩成真实权限系统 | 顶部身份用于演示；本地管理员入口单独鉴权，不承诺生产多租户隔离 |
| X1 真实芯片型号和指标映射没有提供 | 使用标明示例性质的占位，不编造型号；不适用的 GPU 指标显示“—” |
| 内蒙古机房的城市未提供 | 地图使用区域示意，不自选一个城市当成事实 |
| 租赁终止、任务终止、实例终止三入口结果不同 | 统一业务操作处理关系，保证从任一入口结束同一业务得到一致状态 |
| 订单数量暗含多实例，但实例终止被实现成整单终止 | 首版 明确样例关联数量；一单多实例需定义部分终止，不能把剩余正常实例遗留在已结束订单下 |
| 自动刷新导致重复 Token、重复费用和多个计时器 | 时间片或事件只处理一次；刷新用于读取/更新同一来源，不重新生成业务实体 |
| 用量筛选范围与当日/累计 Token 标题矛盾 | 明确两类时间口径并在需要处说明；不静默改变累计含义 |
| 演示数据恢复只重置某一页面 | 按当前发布基线复位运行实体和日志，保持 CMS；恢复出厂另行确认，见 LOCAL_DATA |
