1 项目定位与本轮变更
本项目交付一套 Windows 离线桌面演示软件。用户取得安装包或免安装程序后，可在约定支持的电脑上打开独立应用窗口，使用已确认的 3D 算力调度界面，并进入本地管理后台修改展示内容。软件在第一次启动、查看页面、编辑、保存、重新打开和导出数据时均不依赖互联网。
本轮执行范围为 Windows 客户端、原有完整演示前端、本地管理后台和本地数据库。 原规划中“浏览器持久化、静态网页交付、P1 后端另行启用”的默认决定被本版替换。3D 中国地图视觉、六个导航、八个业务视图、九张主表及算力租赁与 Token 的演示规则继续执行。
项目仍用于客户演示。节点、GPU 利用率、Token 产出、调度、账单和告警采用一致的模拟数据；管理后台的编辑与磁盘保存是真实功能。真实机房、设备、推理、支付和租赁供应商接口不在本次范围。此前另一个产品网站讨论中的手机号注册与实名认证，不自动加入这个离线 CaaS 项目。

2 用户实际使用方式
2.1 安装或免安装运行
推荐普通用户使用完整安装版：取得文件，双击安装，从桌面快捷方式打开。便携演示使用免安装版：复制到本机，双击运行。两种形式都进入软件自己的窗口，不自动打开浏览器，不需要终端窗口常驻。[2]
安装包使用包含全部应用文件的 NSIS 目标，不采用安装时在线下载主体文件的 nsis-web。免安装版启动时可能在本机临时目录释放运行文件，业务数据仍保存在稳定的应用数据目录；“免安装”不代表“不会在电脑写入任何文件”。[2]
用户第一次获取软件可以通过下载或 U 盘拷贝完成。离线要求从取得完整交付文件之后开始，必须覆盖全新电脑上的安装与首次启动，而不只验证曾经联网启动过的开发机。
2.2 展示端与管理端
打开软件默认显示算力总览。侧栏保持六个业务栏目，顶部保留平台名称、演示租户与角色、刷新频率及手动刷新。管理入口放在应用菜单或顶部次要菜单，不占用原来的六个业务栏目。
进入管理后台后打开单独的管理窗口，展示窗口可以同时保留。最多一个展示窗口和一个管理窗口，避免多个写入界面互相覆盖。两者共享主进程中的同一数据仓库和数据库，后台保存并应用后，展示窗口自动收到更新；无需关闭软件或等待下一轮 30 秒刷新。
展示端继续支持原有手动调度、暂停、终止、重试、迁移、续租、告警处理和 CSV 导出。其“只读发布内容”是指不直接编辑后台草稿，并不取消这些原始业务演示交互。
2.3 内容修改与演示维护
普通内容修改采用轻量流程：编辑草稿，查看预览，点击“保存并应用”。草稿可在关闭管理窗口后恢复；只保留一个活动草稿，不建设审批流或多人协作系统。
平台标题、Logo、说明文字、显示编号、图表样式等展示配置更新时，仅合并相应配置，保留当前订单和演示进度。节点容量、资源分配、历史账单、Token 历史基线等关联数据需要成组改动时，进入“编辑演示数据”：暂停模拟时钟和冲突业务操作，校验草稿并查看影响；确认后先备份当前内容，再整体应用新的场景。界面明确告知这次操作会替换当前演示进度。
放弃场景编辑只丢弃结构草稿，保留进入维护时已结算并提交的正式场景，恢复进入维护前的运行或暂停选择，不回滚到更早快照。保存成功以数据库事务提交为准；磁盘不可写、空间不足或校验失败时，不显示虚假的成功信息，不把未保存状态当成已生效内容。

Electron 将 Chromium 和 Node.js 随应用分发，适合继续使用已经规划的网页组件与 3D 界面，并以应用自己的窗口呈现。[1] “类似 Codex 客户端”在本项目中指这种独立客户端体验，不据此推断 Codex 内部实现。
Tauri 也能实现桌面应用，但 Windows 版本依赖 WebView2。严格离线分发需要额外处理离线 WebView2 安装或随包固定运行时；仅携带小型在线引导安装器不能满足首次离线安装。[3] 本项目优先实现既有 Vue 与 3D 方案的稳定分发，因此默认选择 Electron。最终包体、启动时间和内存占用以实测记录，不承诺未经构建验证的数字。
3.2 窗口与数据通信
展示页和管理页运行在各自渲染窗口。页面只通过受限的 preload 接口调用明确能力，例如读取快照、执行业务动作、保存草稿、应用配置、导入导出和打开文件选择框。主进程验证窗口来源、登录状态、参数和版本，再访问本地文件及数据库。[4]
数据库、文件系统和密码校验不放在页面代码中。渲染器关闭 Node 集成，开启上下文隔离和沙箱；不开放任意 IPC 通道、任意路径读写、任意 SQL 或 shell 执行。后台保存的文字按纯文本显示，不能成为可执行 HTML 或脚本。[4]
正式包不启动 Vite 开发服务器，不打开外部浏览器，不依赖常驻 HTTP 端口。开发阶段可以使用本机热更新服务器；生产包通过受限的本地应用协议加载已打包资源。
3.3 SQLite 与应用升级
默认数据目录为 Electron userData 下的固定业务子目录。应用身份和目录名不随客户修改平台展示名称而改变；安装文件、随包种子、只读素材与用户数据分开保存。[5]
所有写入由一个串行服务执行，使用事务保证订单、任务、实例、资源、用量和账单共同成功或共同失败。主进程提交后再广播版本更新；业务动作由 businessRevision 保护，整份显示快照由 runtimeRevision 标记，纯计量不制造业务版本冲突，窗口丢弃旧响应，不用各自的刷新计时器重复推进 Token。关闭应用后模拟时间停止；重新打开从最后保存的演示时刻继续，不补算离线期间的虚构收入或产出。
SQLite 访问库应在 Windows 打包验证阶段尽早确定。若采用原生 Node 模块，必须核查所选 Electron 与 Windows x64 二进制兼容性，必要时按目标重建，并验证打包后的加载，不能用开发态成功代替 exe 成功。[6] 具体依赖版本由最小联合验证后锁定，本规划不虚构已测试的版本组合。

本表中的“可编辑”包括直接编辑展示配置、编辑关联数据来源、通过业务动作改变状态，以及在维护模式下重新编排样例。每个前端字段都必须登记编辑入口或计算来源，不能仍有隐藏在代码里的独立演示常量。详情抽屉、日志、曲线、空状态及筛选选项也在覆盖范围内。
4.2 汇总数字如何修改
总 GPU、已分配、空闲、在线节点数和月租合计由相应实体计算。需要改 GPU 总量时调整节点卡数；需要改月租合计时调整样例租约的价格、数量和有效状态。管理页应展示应用前后影响，例如“总 GPU 320 → 352”，方便操作者直接判断结果。
利用率属于遥测指标，不等同于已分配卡数比例。后台可以设置固定当前值、稳定波动参数或近一小时采样点，但同一时刻的卡片、曲线终点和节点明细必须使用同一数据源。Token 的当日值、历史基线和累计值按统一规则计算，不允许累计值小于当日值。
前端显示的节点号、订单号、任务号可以编辑显示编号；内部稳定 ID 用于关联，不随重命名改变。新增和删除有关联的资源时，管理页展示受影响记录，阻止留下孤立订单、重复分配或缺失详情。
4.3 全部可编辑的明确边界
本版实现固定界面中的结构化内容管理。原有六栏目、七指标卡、3D 地图、表格结构及交互能力是开发交付物，管理端不提供任意拖拽重画页面或编写程序的功能。状态标签可改字面表述，绿色运行、红色异常等业务语义及单位规范保持一致。
四个策略的底层行为沿用原来的固定演示逻辑。可以编辑面向客户的标题和解释文字；算法类型、优先关系与启用状态属于受约束的功能事实，不得只把“是否启用”改成相反显示而继续执行旧行为。本版不提供通用调度规则编辑器；若要编辑策略执行能力，应作为明确的后续功能变更。
X1 的资源类型固定为边缘推理，不提供租赁订单和设备租金。历史账单在当前运行场景中不可直接覆写；如需准备另一套金额样例，可在维护模式编辑新场景，校验并整体应用，原场景保留在备份中。这些约束确保内容可改之后仍能完整演示。
5 数据保存与离线迁移
5.1 本地账号
首次进入管理端创建本地管理员密码，无需联网验证。密码由主进程使用适合密码存储的带盐哈希处理，页面不持有数据库凭据。没有多人协作需求时只实现一个管理员，不增加企业级角色体系。
展示租户和顶部角色继续是演示身份，与本地管理员登录分开。本地密码用于应用内管理入口控制，不能宣称能够抵御拥有该电脑文件权限或系统管理员权限的人修改本地数据。退出管理窗口即清除该窗口管理会话。
5.2 备份与恢复
在整体替换场景、导入和数据库升级前，先创建可恢复的一致快照。活动 SQLite 数据不能简单复制单个数据库文件后就声称已经完整备份；使用数据库备份机制或经过验证的停止写入与检查点流程。[7]
默认保留最近 3 次自动内容备份，管理端可手动导出完整演示数据包。数据包包括版本、配置、实体、历史样例、日志、模拟时钟及必要用户素材；不包含管理员密码、会话、绝对本机路径或开发凭据。导入先校验大小、版本、引用与资源守恒，显示内容摘要，再由用户选择替换当前数据。
损坏或过新版本的数据包应被拒绝，当前数据不受影响。升级遇到不兼容 schema 时保留原文件，给出恢复说明，不能静默清空或退回初始样例。“重置本轮演示”从当前发布基线复位并保留 CMS；“恢复出厂内容”恢复标准内容并清理草稿，保留本地账号；“恢复备份”载入选定内容。会替换内容的动作均先展示影响并确认。
5.3 多台电脑的数据行为
电脑 A 上修改内容后，电脑 B 不会自动变化。可以从 A 导出数据包，通过 U 盘等方式转移到 B，再在 B 导入。复制原安装 exe 只复制软件和随包初始样例，不自动包含 A 的修改；不要把用户数据写回 exe。
首版安装版和免安装版使用同一应用身份，同一 Windows 用户下打开任一形式使用同一数据目录，并用单实例锁避免同时写入。不同 Windows 用户的数据隔离。应用覆盖升级默认保留用户内容；卸载默认不主动删除用户数据，彻底清除另设明确操作。

6.1 视觉基准

7 统一演示数据与业务约束
7.1 默认样例
初始样例继续使用 48 个节点、320 张中心 GPU、212 张已分配、108 张未分配；在线节点 44 个；CPU 共 8192 核、已分配 5120 核；内存 32 TB、存储 512 TB。当日 Token 128.6M、累计 8.42B，24 份有效租约的月度等价租金合计 286400 元。
这些是可复算的演示数据，具体节点、合同、价格和分配对应关系沿用 DATA_RULES。可通过后台准备新场景改变这些数字；恢复标准样例后必须再次得到同一套初始结果。不得将样例标成已接入真实机房的数据。
7.2 关键规则
租赁仅在南宁、成都、内蒙古中心节点运行；X1 无租赁和租金。整机和裸金属按节点独占，GPU 租赁按卡预留，资源不能超卖。租赁调度只迁出所选目标节点上的 Token 任务，无关任务继续运行。
暂停保留资源并停止新增 Token；终止从订单、任务或实例任何入口进入，都执行统一关联流程。迁移原子地释放旧资源并占用目标资源，保留实例 ID 和用量历史分段。确认告警只改变处理状态，不把离线设备自动修好。
金额、用量与 Token 由主进程统一结算；重复请求、窗口刷新、关闭重开不能多计账或复活终止实体。演示月按 30 天，日计费按正持续时间向上取整为天，金额在最终一步四舍五入。原已出账期间与价格快照不被终止、续租或后台展示配置修改反向改写。
7.3 必须可重复的演示
保留租赁优先抢占 Token、边缘新任务不足时回落中心、租赁终止保护历史账单三条主线，并支持终止后的空闲填充支线。额外覆盖续租、失败重试、迁移、告警跳转和 CSV。
新增一条后台完整流程：修改品牌和地图标签，应用后两窗口同步；再进入维护模式编辑一台设备及关联样例，查看汇总变化；关闭软件后重开；导出数据到另一份干净用户环境导入并核对。精确的业务场景预期数值见 DATA_RULES，桌面与管理验收见 ACCEPTANCE_CHECKLIST。

9 验收要求
9.1 离线与桌面
在未安装开发工具的测试 Windows 用户环境，先断网，再安装和首次启动正式交付包。展示、管理、3D 地图、图表、全部模拟操作、保存重开和 CSV 均可用。程序不尝试下载运行时或外部素材，不要求登录在线服务，不依赖曾经缓存过的在线页面。
安装版与免安装版分别测试；应用打开时不跳外部浏览器，不需要手工启动后端。窗口拖拽、最小化、最大化、关闭、全屏退出、中文用户目录及带空格路径均纳入检查。不同机器支持结果应记录系统、架构、GPU、缩放、包版本和文件哈希。
9.2 后台编辑与持久化
全部前端字段建立映射：直接配置、实体字段、历史样例、模拟遥测或计算规则。每个类别至少抽取完整链路验证，汇总数字再逐项核对其来源。后台修改后展示自动更新，切页、手动刷新和软件重启不会恢复旧值。
发布配置不能回滚当前订单进度；维护期间禁止并发业务写入；放弃草稿不影响已发布内容。导入冲突、损坏文件、超容量、边缘租赁、失效引用和磁盘保存失败要有明确可恢复结果。未登录管理端不能通过直接调用 IPC 绕过管理操作限制。
9.3 视觉与业务
原逐页清单及三条主场景全部通过，首页保留批准的空间层次与可交互 3D。测试三个窗口尺寸与系统缩放；地图标签与点位对齐，切页和关窗释放图形资源。帧率以目标演示机实测；30 FPS 可作为该机目标，不承诺所有显卡均相同。
使用少量有价值的测试覆盖事务原子性、资源守恒、X1 禁租、终止幂等、历史账单、Token 去重、发布冲突及导入恢复。通过类型检查、构建与打包后，仍需实际运行最终 Windows 包；Linux 上生成了一个文件不能证明 Windows 安装与离线使用已通过。
Windows 签名和企业策略可能影响分发体验，发布前记录签名状态与干净机结果，不承诺任何 exe 在所有电脑上都不会出现提示。若后续面向公众分发，可按发布主体配置合法代码签名；不要求客户关闭安全软件来满足验收。[8]
